# AwareLab 30 分钟培训讲稿

给**演练值守人**讲的稿子，不是给开发讲的。听众是安全团队里第一次上手这个平台的人，
讲完他应该能独立跑完一次演练、并在出岔子时知道先按哪个刹车。

配套材料：[使用手册](使用手册.md)（逐步截图级说明）、[演练值守与缺陷分级](演练值守与缺陷分级.md)（出事时翻）、
[部署与运维手册](部署与运维手册.md)（装机器的人翻）。本稿只讲**一次演练怎么跑**，不重复安装与排障。

讲法建议：全程投屏一个已经起好的实例，边说边点。不要放幻灯片念字段名——字段名界面上都写着，
值守人真正记不住的是**顺序**和**哪一步不能省**。

## 00:00–03:00 开场：这是什么、不是什么

先说清楚定位，否则后面每一步都会被当成"钓鱼工具"来问。

> 这是一个**安全意识演练**平台。它做的事情是：在拿到书面授权的前提下，
> 仿一个登录页、发一封假邮件，看有多少员工会把口令填进去，然后把这些人挑出来做教育。
> 采到的口令是证据，不是战利品。

三条红线，讲的时候一条一条停顿，别连着念完：

1. **只在授权范围内使用。** 平台把这句话做成了硬门禁：没有生效中的授权记录，建钓鱼网站会被直接拒绝，
   已经建好的网站也会停止服务。不是提醒，是拦。
2. **不做反溯源、不做免杀、不做凭据转发。** 邮件里带打开像素、链接带令牌，这些都是**故意留痕**的——
   演练要能对账。任何"让它更像真的、更难被查出来"的需求都不在范围内，提了也不会做。
3. **采到的口令按敏感数据管。** 界面上默认是掩码，看明文要单独点、单独留审计；
   交付给甲方的报告与 CSV 里口令一律掩码、员工邮箱部分掩码。只有操作员自用的取证件是明文。

一句收尾：

> 判断一个动作该不该做，只问一句——**这件事写进授权文件和审计报告里，我敢不敢签字。**

## 03:00–08:00 第 1 步 登记授权

投屏：顶栏「演练授权」→「登记新授权」。

**要讲的字段只有三个**，其余照界面填：

- **「允许仿冒的域名或标记（每行一个）」**——这一份名单同时管两件事：钓鱼网站接受哪些 Host、
  链接改写允许跳到哪。三种写法：
  - `corp.example.com` 精确匹配；
  - `*.mail.example.com` 泛域名，**含裸域** `mail.example.com`；
  - `#ip` 只允许直接用 IP 访问，内网没有域名时用这条。
  - 讲这里要强调一句：**名单写宽了，演练范围就宽了。** 授权文件上写的是哪个域，这里就只写哪个域。
- **「有效期」**——选 7 / 30 / 90 天或自定义；过期后钓鱼网站自动停服，访客看到「演练授权已过期，页面已停止服务。」
  续期就是回来把有效期往后推，改期时弹窗会重新要求勾选合规确认。
- **「合规确认」**——勾选一次即可，框里写明"已获得被测单位的书面授权，并承诺仅在上述时间与域名范围内开展演练"。
  承诺原文仍原样写进授权记录，但不再要求逐字抄写；这不是形式主义，它是事后争议里"操作者当时知道边界"的直接证据。

演示动作：填完 → 勾上合规确认 →「登记并解锁」变可点 → 点它 →
指顶栏徽标从「未授权 · 平台已锁」变成「授权生效」。

**这一段最重要的一句话**，讲完停下来看着听众说：

> 演练结束或者场面失控时，你要按的按钮是这一行的**「吊销」**。
> 它会把这条授权名下**所有**钓鱼网站当场停掉，比逐个网站手点「停止」可靠，也不会有人忘。
> 现在先找到它在哪，别等出事再找。

顺手演示吊销的确认框文案（「将同时停止其下所有钓鱼网站监听，确认？」），然后取消，不要真吊销。

常见提问：
- *已吊销的授权能改回来吗？* 不能，服务端返回 409。要再演练就登记一条新的。
- *授权没到期但想提前收？* 用吊销，不要去改结束时间——改时间是"续期"语义，留痕也不一样。

## 08:00–12:00 第 2 步 备料

投屏：顶栏「钓鱼素材」，四个标签页过一遍名字就行，重点只讲**假登录页**。

演示动作：新建 → 「插入骨架」拿起手模板 → 「立即诊断」→ 指着列表里的「诊断分」。

诊断有五项：**采集绑定 / 提交触发点 / 外部资源 / 自定义脚本 / 可采集字段**。
只需要重点讲一项：

> **「提交触发点」这一项没过，就不要投放。**
> 它盯的是页面里到底有没有能触发提交的控件。老模板爱写
> `<input type="button" value="立即核验" onclick="login()">`，它不产生 submit 事件——
> 历史上就出现过"目标明明点了，上钩记录一条没有"。
> 现在运行时对这种按钮有兜底，采得到，但**别把证据押在兜底上**：
> 这一项没过扣 25 分，改成 `<button type="submit">` 或加 `data-al-collect` 才稳。

然后强调行内「预览」：

> 诊断分高不代表肉眼看着像。**预览这一步别省**，它是唯一能看出"这页一眼假"的地方。

其余三个标签页各一句话：

- **邮件文案**：主题与正文模板，支持变量占位；链接会被自动改写以便记账，正文自动嵌打开像素。
- **上钩教学**：员工上钩之后看到的教育页。注意界面那句「教学页只增不改：保存会生成一条新的教学页记录」——
  这是为了不让历史记录被事后修改。
- **一键仿站**：给个目标地址生成草稿，**只产出草稿，仍需你审**。它同样受授权名单约束。

顺带讲删除保护：删假登录页时如果仍被演练网站引用，服务端会拒绝——先下线网站再删素材。

## 12:00–16:00 第 3 步 建钓鱼网站 + 专属链接

投屏：顶栏「钓鱼网站」→「新建钓鱼网站」。抽屉四区：**绑定素材 / 访客怎么访问 / 本机监听 / HTTPS（可选）**，
最下面还有一块「链接拼接结果」实时预览。

要讲的坑只有三个：

- **先选「访问方式」**：外网域名由 nginx 转进来就选「域名反代」，访客看到的链接到此为止、**不带 `:8080`**；
  访客直接访问 `ip:端口` 才选「IP:端口直连」。这一项选错，链接不是多出端口就是只剩个 `127.0.0.1`。
- **端口必须落在 `capture.port_range`（默认 8000–9999）之内**，越界会报「监听端口需在 8000-9999 之间」。
- **域名要与授权名单对得上**，否则访客请求会被 404 拒绝。
  这个 404 是刻意的：名单外的 Host 打到这个端口上，平台不认。

演示时可以故意把访问方式选成「IP:端口直连」再填域名 `phish.example.com`，预览立刻变成
`http://phish.example.com:8080/` 并弹出黄色提醒——这就是以前邮件链接一眼假的原因，现场改回「域名反代」即可。

行内四个动作，重点讲两个：

- 「停止」/「开启」：**没有二次确认**，点了就生效。停止后提示「已停止监听，历史采集记录保留」——
  讲清楚"下线不等于销毁证据"。
- 「链接与上钩」：不跳页，右侧抽屉里看**这一个网站**的全貌。上面是本站签发过的每条链接
  （归属、打开次数、提交次数、采到的字段名、行内「复制链接」），下面是本站的上钩记录，
  **点记录行左边的箭头展开就是逐字段采集明细**。

演示动作：点「生成专属链接」→ 弹窗里填一个邮箱 → 签发 → 表格立刻多一行 → 复制链接。

这里要讲清一个口径，很多人第一次会搞错：

> 弹窗提示是「为该链接登记归属邮箱；留空则签发匿名访客链接，只计打开不认人」。
> **要给具体人打分就填邮箱；只想测页面效果就留空。**
> 一个链接一个令牌，令牌就是"这条记录归谁"的唯一依据——
> 十个人共用一条链接，你就只能知道"有十个人上钩了"，不知道是谁。

常见提问：
- *链接发出去之后还能改归属吗？* 不能，重新签一条。
- *删除网站会删掉证据吗？* 不会。确认框写的是「已采集的证据保留」。

## 16:00–21:00 第 4/5 步 邮件任务与沙箱复核

投屏：顶栏「钓鱼邮件」，两个标签页。

**发信邮箱**（1 分钟）：点「新增账号」填 SMTP。只讲一件事：

> 口令字段**只写不读**——保存后回显是掩码 `******`，再次保存时留空或原样回填掩码都等于"不改这枚口令"。
> 想真的改掉必须填新值。模型服务的 API Key 同理。

然后点行内「连通性测试」：**先打一发再上任务**，省得到时候分不清是配置错了还是演练被拒。

**发送任务**（1 分钟）：抽屉四区「基础信息 / 素材绑定 / 收件人 / 发送控制」。
提醒两点：收件人可以「导入收件人」批量粘贴；导入完看行内「发送」按钮是否点亮（总数为 0 时是灰的）。

**沙箱复核**（3 分钟，这一段是重点）：

「发送控制」里的**「沙箱模式」开关**默认是开的。开着点「发送」，邮件不出网，
渲染成 RFC822 文本落到：

```
server/data/outbox/<任务ID前8位>-<收件人邮箱>.eml
```

文件名带 `X-Sandbox: true` 头，成功提示「沙箱发送完成 N 封，正文已落到 server/data/outbox 供复核」。

演示动作：真的去打开一个 `.eml`（用邮件客户端），一项一项念：

> 主题里的变量展开了没有、正文渲染崩了没有、链接改写后的域名是不是授权名单里那个、
> 像素地址能不能连通、附件齐不齐。
> **沙箱里发现的小错，真实发信时就是一次事故。**

再讲收件人四种状态与重发口径：`pending` / `sandboxed` / `sent` / `failed`。

> 「发送」只处理 `pending` 和 `failed` 的人——已经 `sandboxed` 的不会重复发送，这不是 bug。
> 想再打一次就单独点「重发」，它会先把该收件人退回 `pending` 再投。

最后讲切「真实发信」：关掉沙箱开关时界面亮红条「风险提示：真实发信已开启」，
并且会强制确认。条件不满足服务端会拒：「演练授权无效或已过期，任务拒绝发送。」
或「未配置发信邮箱，无法真实发送。」

> 切真实发信前确认三件事：授权在生效窗口内、已绑定可用发信邮箱、收件人名单就是授权名单。

## 21:00–26:00 第 6 步 看证据、做教育闭环、出报告

投屏：顶栏「上钩记录」第一屏（分组看板）。

**先讲看板口径**（2 分钟），这是最容易被人质疑数字的地方：

- 两张表：「按钓鱼网页分组」一行一个钓鱼网站，「按钓鱼邮件分组」一行一个发送任务。
- **网页组**只统计这个网站上的网页采集，所以进去后没有「类型」筛选；
  **邮件组**把同一个任务发出去的整条链算在一起（打开像素 + 链接点开 + 页面提交），所以「类型」筛选还在。
- **看板数字与点进去左上的「共 N 条」永远相等**——两处用的是同一套过滤条件。
- **没钓到人的载体也照样挂在板上**（上钩终端 0）。一行都不能少，
  否则"这个页面没人上当"这个结论本身就没处可查。已删的网站与任务也出现，标签写「已收网」「任务已删」。

**再讲处置状态与教育闭环**（2 分钟）——这是演练的价值所在，不是采到多少口令：

> 每条上钩记录有一个处置状态：**未处置 / 已联系 / 已教育 / 已关闭**。
> 可以单条标记，也可以勾选批量标记。看板和首页都会给出「教育覆盖率」——
> 已教育 + 已关闭 占总数的比例。
> 演练的交付物不是"钓到 37 个人"，是"这 37 个人都受教育了"，覆盖率就是这句话的证据。

演示动作：勾两条 → 批量标记「已教育」→ 指看板上的覆盖率变化 →
点一条记录看详情里的「提交历史」（同一终端多次提交都会保留）与「采集字段」。

**讲掩码口径**（30 秒，必讲，否则值守人会以为平台在藏东西）：

> 采集值在界面上默认掩码。要看明文得单独点「显示明文」，**这一下会进审计**（`record.secret_reveal`）。
> 这不是防你，是防"谁在什么时候翻过谁的口令"说不清。

**最后讲三种导出物的区别**（30 秒）：

| 出口 | 内容 | 给谁 |
| --- | --- | --- |
| 「导出网页证据 / 邮件证据」CSV | **明文**，12 列含处置状态 | 操作员自用的取证件 |
| 按授权生成的演练报告（HTML） | 口令掩码、员工邮箱部分掩码、含承诺语句 | 交给甲方 |
| 按授权导出的交付 CSV | 同上，表头写明「采集内容(凭据已掩码)」，带 BOM 可直接用 Excel 开 | 交给甲方 |

> 交付件里连"员工填在账号框里的邮箱"也会部分掩码——那份名单可能流转多方。
> 三份都会写导出审计（`report.export`），审计里不抄报告内容。

顺带指一下「操作审计」页：它记的是**谁动了平台**（授权增删改、关闭沙箱、发送、导出、删除、改运行参数），
与「通知记录」（平台往外发了什么）分职。**这张表只读，没有改和删的接口**——
理由很直白：审计一旦能事后修饰，就不再是审计。

## 26:00–29:00 第 7 步 收尾与数据留存

**收尾动作只有一个**：回到「演练授权」点该行的「吊销」。

> 这会同时停掉名下所有钓鱼网站监听，是最干净的一次性刹车。
> 吊销后访客再访问会得到 403「当前无有效演练授权…」。

然后归档：导出 CSV、`server/data/outbox/` 的 `.eml`、演练报告，按授权文件约定处理原始凭据。

**讲数据留存**（1 分钟）——这一段是 M2 之后新增的，很多老值守人不知道：

> 平台按 `exercise.retention_days` 自动清理过期数据，**默认 180 天**；
> 审计日志走另一条更长的 `audit_retention_days`，**默认 365 天**。
> 为什么审计要比数据活得久：审计是"谁动过什么"的自证材料，
> 与数据同生死的话，授权方的复核窗口会比数据留存窗口还短。
> 清理是每天自动跑的，也可以在「系统设置」里手动跑一次**试算**（只算会删多少，一条不删），
> 确认了再真删。真删会写两条审计：先写"打算删多少"，再写"实际删了多少"——
> 中途被杀也留得下现场。
> 配成 `0` 就是**永不清理**，长期留存证据的部署走这条。

**讲账号安全**（1 分钟）：

> 后台口令要在「系统设置 → 账号与口令」里改掉，出厂口令没改的话平台会**拦住建站**（409），
> 这是刻意的：一个能采集凭据的工具挂着出厂口令上线，比演练本身风险大。
> 改口令会作废**所有**已签发会话，包括你自己这条——改完要重新登录，这是正常现象。
> 同一页能看当前所有登录会话（只给令牌前几位）、能一键「退出所有会话」——
> 笔记本丢了或者有人在旁边登录过，就用它。
> 登录连续失败 8 次会锁 10 分钟，**重启不清零**（计数落库）。被锁了要么等，要么让运维手工清表。

## 29:00–30:00 交接：检查表与求助路径

留一分钟指路，不要展开：

1. **发布/上线前**：跑 `node server/scripts/ci.mjs`，对照
   [部署与运维手册 §10 发布检查表](部署与运维手册.md) 把人工那几条勾完。
2. **演练中出事**：翻 [演练值守与缺陷分级](演练值守与缺陷分级.md)——
   里面写了哪几级要立刻吊销授权、哪几级可以撑到窗口结束。
3. **不懂某个词**：翻 [术语对照表](术语对照表.md)（界面用大白话，接口和数据库用的是另一套）。
4. **要装机器 / 改端口 / 恢复备份**：翻 [部署与运维手册](部署与运维手册.md)。

最后一句收尾：

> 这个平台的每一个"多此一举"——授权要勾合规确认、看明文要留审计、审计表不给改、
> 沙箱默认开着、出厂口令不让建站——都是为了让演练结束后，
> 你能拿着一份东西说清楚"我在授权范围内做了什么、采到了什么、谁受过教育"。
