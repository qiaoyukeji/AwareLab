# AwareLab 部署与运维手册

> 面向**部署这台机器的人**：怎么装起来、怎么让它开机自启、怎么备份、怎么在演练结束后把数据清干净、出问题先看哪一行日志。
> 面向**用这个平台的人**（怎么登记授权、怎么建站发信查证据）请看 [使用手册](使用手册.md)。
> 演练进行中出问题时的响应时限与止血动作见 [演练值守与缺陷分级](演练值守与缺陷分级.md)。

红线先说清楚：`server/config.yaml` 里有后台口令、`server/data/` 里有演练采集到的真实口令。
这两处**任何情况下都不进版本库、不进聊天工具、不进工单截图**。手册里所有涉及口令的地方都只说"在配置文件里"。

## 1. 环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | **≥ 22.5** | 平台用内置 `node:sqlite` 作数据库（[server/src/platform/storage/connection.js:102](../server/src/platform/storage/connection.js#L102)），低版本会在 `import` 处直接崩。版本口径同时写进两端 `engines`（[server/package.json:17](../server/package.json#L17)、[web/package.json:15](../web/package.json#L15)），`node -v` 先确认 |
| npm | 随 Node 附带 | 只在安装依赖与前端构建时用；本手册所有命令都写成 `npm --prefix …`，可以在仓库根直接贴 |
| 操作系统 | Linux / macOS / Windows | Windows 上命令用 Git Bash 或 PowerShell 都可以，路径分隔符不敏感 |
| 内存 / 磁盘 | 512MB / 2GB 起 | 磁盘主要被 `data/screenshots` 吃掉，上限见 `capture.callback.screenshot_quota_mb`（[server/src/platform/settings.js:104](../server/src/platform/settings.js#L104)） |
| 浏览器 | Chrome / Edge 近两年版本 | 管理界面用 Vue 3 + Element Plus（[web/package.json:24](../web/package.json#L24)） |

需要放行的端口：

| 端口 | 谁用 | 该不该对外开放 |
| --- | --- | --- |
| 7778 | 管理面 + 信标面（同一个进程，[server/src/platform/settings.js:62](../server/src/platform/settings.js#L62)） | **不该**。默认只绑 `127.0.0.1`（[server/src/platform/settings.js:65](../server/src/platform/settings.js#L65)），远程管理走 SSH 隧道 |
| 7777 | 前端 dev server（只有开发时用，[web/vite.config.js:27](../web/vite.config.js#L27)） | 不该。生产环境用构建产物，不起 dev server |
| 8000–9999 | 采集面，每个钓鱼网站占一个（[server/src/platform/settings.js:89](../server/src/platform/settings.js#L89)） | **该**。演练对象要能访问到仿冒页，这段要按范围开口 |

7778 上同时跑着两个平面，这是刻意的：管理面挂在 `/{32位随机路径}/` 下，信标面挂在 `/alab/` 下，
两者共用一个监听端口，部署时只需要管一个端口的防火墙与反代
（挂载顺序见 [server/src/boot/main.js:67-70](../server/src/boot/main.js#L67-L70)：信标面先挂，管理面的 SPA 通配兜底最后挂）。

## 2. 从零部署（照抄可跑）

```bash
# 1) 取代码
git clone https://gitee.com/qiaoyukeji/AwareLab.git
cd AwareLab

# 2) 装依赖（后端与前端各一份）
npm --prefix server install
npm --prefix web install

# 3) 构建前端（管理界面是构建产物，由后端进程直接托管）
npm --prefix web run build

# 4) 准备配置：可以直接启动让它自动生成，也可以复制样例自己改
cp server/config.example.yaml server/config.yaml
#   —— 至少改这三项：panel.username、panel.password、panel.path（换成自己的 32 位十六进制随机串）

# 5) 启动
npm --prefix server start
```

首次启动（`server/config.yaml` 不存在时）会自动生成一份（[server/src/platform/settings.js:147-152](../server/src/platform/settings.js#L147-L152)）：随机后台路径 + 随机账号 + 随机口令，
并把文件路径打印一行（[server/src/boot/main.js:87](../server/src/boot/main.js#L87)，只有"本次真的生成了配置"才打，第二次启动不再重复提示）。此时**立刻做两件事**：

1. 打开 `server/config.yaml`，把 `panel.username` / `panel.password` 抄到密码管理器里；
2. 登录后台，在「系统设置 → 账号与口令」里改掉这条出厂口令。

样例文件 [server/config.example.yaml](../server/config.example.yaml) 里的示例值就是它的写法：
`panel.path` 用 32 个 `0` 占位、`username` / `password` 都写 `change-me`、`bind: 127.0.0.1`、`trust_proxy: false`、
`capture.port_range: [8000, 9999]`、`bind_host: 0.0.0.0`、`mail.default_dry_run: true`、`default_send_interval_ms: 3000`、
`exercise.require_authorization: true`、`session_ttl_hours: 12`。**这些是样例值，不是生产值**——照抄 `change-me` 上线等于把口令写在门上。

第 2 步不做，建站会被挡住：OPS-04 的判定是"`password_updated_at` 为空 = 还在用出厂随机口令"（[server/src/platform/configCheck.js:34-36](../server/src/platform/configCheck.js#L34-L36)），
此时 `POST /web-sites` 返回 **409**（[server/src/api/siteApi.js:75-76](../server/src/api/siteApi.js#L75-L76)），提示先改口令。这是设计，不是故障（见 §5）。

验证部署成功的最短路径（不需要登录）：

```bash
curl -i http://127.0.0.1:7778/alab/health      # 期望 200 + ok
```

启动横幅会打印管理后台地址（含随机路径，[server/src/boot/main.js:90](../server/src/boot/main.js#L90)）。**不要把这行贴到任何群聊或工单里**——
随机路径是"挡住扫描器"的门槛，不是鉴权；泄露路径 + 口令被猜中 = 全部演练数据归对方。

### 开发模式（改前端时用）

```bash
npm --prefix server start        # 后端 7778（要热重启可用 npm --prefix server dev，即 node --watch）
npm --prefix web run dev         # 前端 dev server 7777
```

浏览器开 `http://127.0.0.1:7777`。dev server 会把 `/api` 代理到 `http://127.0.0.1:7778/{随机路径}/api`——
随机路径与端口是从 `server/config.yaml` 里正则读出来的（[web/vite.config.js:10-21](../web/vite.config.js#L10-L21)、[web/vite.config.js:28-35](../web/vite.config.js#L28-L35)），
所以**没有 `server/config.yaml` 时代理是空的**（前端会拿不到后台路径），先按上面第 4 步把配置准备出来。
改 `panel.path` 后要重启 dev server，它只在启动时读一次那个文件。

**改完前端要上线必须重新构建并重启后端**：管理面的 SPA 外壳是在挂载时一次性读进内存的
（[server/src/channels/adminPlane.js:34](../server/src/channels/adminPlane.js#L34) 读 `web/dist/index.html`，[server/src/channels/adminPlane.js:56-64](../server/src/channels/adminPlane.js#L56-L64) 只在挂载时判一次有没有构建产物），
所以 `vite build` 之后不重启后端，界面还是旧的；`web/dist` 压根不存在时后台走 503 提示而不是崩溃。

## 3. `config.yaml` 逐项说明

默认值全部写在 [server/src/platform/settings.js:55-135](../server/src/platform/settings.js#L55-L135) 的 `DEFAULTS` 里，下面这张表就是照它抄的。三条通用规则先说：

- **没写某一项不会报错，会退回默认值**（合并逻辑 [server/src/platform/settings.js:156-163](../server/src/platform/settings.js#L156-L163)）；
- **改完要重启进程才生效**，配置只在启动时读一次，没有热加载（同上文件头「坑②」，[server/src/platform/settings.js:14](../server/src/platform/settings.js#L14)）；唯一在运行期写回文件的动作是「改后台口令」；
- **合并只做两层**（顶层 + 每个二级块，见 [server/src/platform/settings.js:160-163](../server/src/platform/settings.js#L160-L163)）：写了 `capture.callback` 里的一个键，`callback` 这一整块会被**整体替换**，同块其余阈值的默认值就没了。目前唯一读这块的是信标面，它自带兜底常量（[server/src/channels/beaconPlane.js:46-53](../server/src/channels/beaconPlane.js#L46-L53)），所以回传闸门不受影响；但这条坑记录在案（[server/src/platform/settings.js:11-13](../server/src/platform/settings.js#L11-L13)），**要改就整块抄全再改**，别只写一行。

数据目录与配置文件的位置可以用环境变量整体挪走：`AWARELAB_DATA`、`AWARELAB_CONFIG`（[server/src/platform/settings.js:30-31](../server/src/platform/settings.js#L30-L31)）。
不设就落在 `server/data` 与 `server/config.yaml`。这两个变量是给隔离验证用的钩子，也是你唯一的"在副本上试"的手段（见 §8）。

### panel（管理面）

| 键 | 默认 | 改了会怎样 / 什么时候该改 |
| --- | --- | --- |
| `path` | 随机 32 位十六进制（[settings.js:60](../server/src/platform/settings.js#L60)） | 后台入口路径。只在首次生成时随机，之后一直沿用文件里的值，否则收藏的地址每次重启都变。换了等于换入口，不影响鉴权 |
| `port` | 7778（[settings.js:62](../server/src/platform/settings.js#L62)） | 管理面与信标面共用端口。写成非 1-65535 的整数会**拒绝启动**（[configCheck.js:68-71](../server/src/platform/configCheck.js#L68-L71)）。采集面不许占用本端口，见 §6 |
| `bind` | `127.0.0.1`（[settings.js:65](../server/src/platform/settings.js#L65)） | 改成非回环地址 = 后台对同网段开放，启动时打一条 `[提醒]`（[configCheck.js:95-101](../server/src/platform/configCheck.js#L95-L101)）。写成空/null 时代码兜回 `127.0.0.1`（[main.js:45](../server/src/boot/main.js#L45)），不会悄悄变成全网卡 |
| `username` / `password` | 随机 8 位（[settings.js:68-69](../server/src/platform/settings.js#L68-L69)，字符表去掉了易混字符） | **明文存储、登录全等比对、不做 hash**（[settings.js:66-67](../server/src/platform/settings.js#L66-L67)）。所以这个文件等同于口令本体，绝不入库 |
| `password_updated_at` | `null`（[settings.js:73](../server/src/platform/settings.js#L73)） | 由「改口令」接口写入（`persistConfigValue`，[settings.js:129](../server/src/platform/settings.js#L129)）。`null` = 还在用出厂口令，会触发 §5 的建站闸门 |

## 4. 服务化（开机自启）

### Linux · systemd

```ini
# /etc/systemd/system/awarelab.service
[Unit]
Description=AwareLab 安全意识演练平台
After=network.target

[Service]
Type=simple
User=awarelab
WorkingDirectory=/opt/AwareLab/server
ExecStart=/usr/bin/node src/boot/main.js
Restart=on-failure
RestartSec=5
# 演练期间不要让它被 OOM killer 之外的东西悄悄停掉；停机顺序由进程自己处理（先收采集面再关主端口）
KillSignal=SIGTERM
TimeoutStopSec=20
# 数据与配置都在 WorkingDirectory 下，不给额外写权限
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now awarelab
journalctl -u awarelab -f          # 看启动横幅与 [提醒]
```

日志会进 journald。**启动横幅不含口令**（口令只留在 `config.yaml` 里，这是 SEC-01 的明确要求），
但含后台随机路径，所以 journald 的读取权限要按"含敏感信息"来管。

### Windows

用计划任务在登录时启动，或用 nssm 注册成服务：

```powershell
nssm install AwareLab "C:\Program Files\nodejs\node.exe" "src\boot\main.js"
nssm set AwareLab AppDirectory "E:\AwareLab\server"
nssm set AwareLab AppStdout "E:\AwareLab\logs\out.log"
nssm set AwareLab AppStderr "E:\AwareLab\logs\err.log"
nssm start AwareLab
```

日志文件同样含后台路径，按敏感文件管权限。

### 优雅停机

进程收到 `SIGTERM`/`SIGINT` 后按固定顺序收（处理函数注册在 [server/src/boot/main.js:109-110](../server/src/boot/main.js#L109-L110)）：
**先 `stopAllSites()` 掀掉所有仿冒端口，再 `server.close()` 关主端口**（[server/src/boot/main.js:103-105](../server/src/boot/main.js#L103-L105)，收端口本体见 [server/src/capture/siteRegistry.js:125-128](../server/src/capture/siteRegistry.js#L125-L128)）。
反过来就等于先失去后台、留一堆钓鱼页面在公网可达的状态下裸奔，没人能一键收掉。
保留期清理的定时器会先停掉（同文件 132 行），它本来就 `unref` 过，不拖退出。
`close()` 的回调里才 `process.exit(0)`，所以还有在途请求时会等它写完——**没有超时强杀逻辑**（同文件 126-127 行注释），`TimeoutStopSec` 给 20 秒足够，不要设成 1 秒。

端口残留的后果写在这里：残留的采集端口会让下一次启动直接报冲突（[server/src/capture/siteRegistry.js:124](../server/src/capture/siteRegistry.js#L124)），
所以看到 `kill -9` 之后重启一片 `status=error`，先想到这一层。

## 5. 启动摘要与配置体检（OPS-04）

体检模块：[server/src/platform/configCheck.js](../server/src/platform/configCheck.js)；启动链路里的调用点：[server/src/boot/main.js:33-40](../server/src/boot/main.js#L33-L40)。

## 6. 站点自动恢复与端口冲突

### 重启自动恢复

重启不该把演练打断：进程启动时会把库里 `status='open'` 的站点重新起监听
（`restoreSites()`，[server/src/capture/siteRegistry.js:110-122](../server/src/capture/siteRegistry.js#L110-L122)，调用点 [server/src/boot/main.js:105-106](../server/src/boot/main.js#L105-L106)），
横幅打印 `已恢复 N 个演练站点监听`；返回 0 就一行都不打。
恢复失败不在这里报错：端口冲突等失败由 `listen` 的异步 error 回调把该行写成 `status='error'`（[siteRegistry.js:85-88](../server/src/capture/siteRegistry.js#L85-L88)）。

两个口径要分清：`web_sites.status` 是**运维意图**，进程里的实况表（`listeners`）才是**在不在听**，两者可以不一致——
界面与证据页判"是否在听"一律走 `isRunning()`（[siteRegistry.js:10-12](../server/src/capture/siteRegistry.js#L10-L12)）。

### `close_reason`：为什么这个站点没被自动放回去

`web_sites.close_reason` 由 v4 迁移追加，取值口径写在 [server/src/platform/storage/schema.js:45-46](../server/src/platform/storage/schema.js#L45-L46)：

| `close_reason` | 谁写的 | 含义 | 授权续期时会不会自动复服 |
| --- | --- | --- | --- |
| `authorization` | 平台（授权出窗口级联下线，[siteRegistry.js:124-133](../server/src/capture/siteRegistry.js#L124-L133)） | 被**强制**下线 | **会**：`reopenSitesOfAuthorization()` 只挑这一类，且复服后把原因清成 NULL（[siteRegistry.js:94-100](../server/src/capture/siteRegistry.js#L94-L100)） |
| `manual` | 操作员（收网 `POST /web-sites/:id/stop`，[siteApi.js:164-169](../server/src/api/siteApi.js#L164-L169)；建档时就选 `status=closed` 也算 manual，[siteApi.js:103-104](../server/src/api/siteApi.js#L103-L104)） | **主动**收网 | **永远不会**：任何续期动作都不许把操作员撤掉的页面重新掀开（QA-10 的根因） |
| `NULL` | 站点在监听中，或复服/开站后清空（[siteApi.js:146](../server/src/api/siteApi.js#L146)） | 没有"为什么下线"要记 | 不适用（它本来就开着） |

坑：清 `NULL` 这一步不能省。留着 `authorization` 的话，窗口一抖动就可能把操作员主动收网的意图冲掉（[siteRegistry.js:91](../server/src/capture/siteRegistry.js#L91)）。
另注意：`restoreSites()` 只看 `status='open'`，**不看授权**——被强制下线的站点在库里已经是 `closed`，所以根本不在恢复集合里；要恢复投放得去界面点开启或走续期复服。

### 端口冲突与端口越界

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 建站/改站回 **400**，提示"监听端口需在 8000-9999 之间" | 端口落在 `capture.port_range` 外（校验本体 [siteRegistry.js:52-56](../server/src/capture/siteRegistry.js#L52-L56)，调用点 [siteApi.js:87-88](../server/src/api/siteApi.js#L87-L88)） | 换一个区间内端口。区间本身可以改配置，但改之前先想清楚防火墙 |
| 建站/改站回 **400**，提示"该监听地址与端口已被其它站点占用" | 同一 `listen_ip:listen_port` 属于别的站点（库里 `UNIQUE(listen_ip,listen_port)`，[schema.js:43](../server/src/platform/storage/schema.js#L43)） | 换端口或先把旧站点撤了。改自己这条记录不算冲突（判定时排除了自身 id，[siteRegistry.js:57-59](../server/src/capture/siteRegistry.js#L57-L59)） |
| 界面显示"开启中"、端口上其实没在听 | 平台外的进程占着那个端口——`portError()` **只查库、不查真实 socket**（[siteRegistry.js:50](../server/src/capture/siteRegistry.js#L50)），要到 `listen` 时才由异步回调发现 | 用下面的命令找出占用者，释放或改端口后重开站点 |
| 主端口起不来，进程直接崩，日志是 Node 原始 `EADDRINUSE` | 7778 被别的进程占了 | 这是**部署问题**，刻意不兜：兜住会让操作员以为服务已经起来了（[main.js:73-74](../server/src/boot/main.js#L73-L74)）。找出占用者或改 `panel.port` |
| 采集端口冲突，单个站点起不来 | 8000–9999 里某个端口被占 | 界面上改该站点的监听端口，重启该站点 |

区间设计本身就避开了 7777 / 7778：8000-9999 这一段"防止误占系统端口与把平台自己（7778）、前端 dev（7777）撞掉"
（[siteRegistry.js:46-47](../server/src/capture/siteRegistry.js#L46-L47)，区间选段理由见 [settings.js:86-88](../server/src/platform/settings.js#L86-L88)）。
**如果你把 `capture.port_range` 改成包含 7777/7778，端口校验就拦不住"自己撞自己"了**——库里的 `UNIQUE` 只约束站点之间，不约束平台端口。
所以别把区间往下探到 1024 以下（要特权），也别把 7777/7778 圈进去。

排查端口占用：

```bash
# Linux（列出 7778 与 8000-8999 段的监听及进程）
ss -ltnp | grep -E ':(7778|80[0-9][0-9])\b'
```

```powershell
# Windows（先找端口，再用 PID 反查进程名）
netstat -ano | findstr ":7778"
Get-Process -Id <上面输出的 PID>
```

## 7. 备份与恢复

### `data/` 里都有什么

数据目录默认是 `server/data`，由 `AWARELAB_DATA` 整体挪走（[server/src/platform/settings.js:30](../server/src/platform/settings.js#L30)），路径集合在 [settings.js:112-123](../server/src/platform/settings.js#L112-L123) 一次拼好，别处不再各自拼相对路径（防止"从哪个目录启动"改变数据落点）。

| 路径 | 是什么 | 备份要紧不要 |
| --- | --- | --- |
| `awarelab.db` | 唯一的库文件（[settings.js:120](../server/src/platform/settings.js#L120)）：授权、站点、模板、任务、上钩记录、事件、审计全在里面 | **最要紧** |
| `awarelab.db-wal` / `-shm` | WAL 日志与共享内存索引，运行期正常存在（`PRAGMA journal_mode = WAL`，[connection.js:107](../server/src/platform/storage/connection.js#L107)）。**最新写入可能还在这里没落回主库** | 冷备要一起带上 |
| `uploads/` | 操作员的仿站素材目录（进程启动时建，[settings.js:140-142](../server/src/platform/settings.js#L140-L142)） | 要。保留期清理**刻意不碰它**，因为删了等于毁配置（[maintenance.js:61-65](../server/src/platform/maintenance.js#L61-L65)） |
| `screenshots/` | 采集到的访客页面截图，落盘见 [channels/beaconPlane.js:252](../server/src/channels/beaconPlane.js#L252)，总量受 `capture.callback.screenshot_quota_mb` 管 | 看业主是否要求留证据 |
| `attachments/` | 回传附件与邮件附件，按 UUID 扁平命名 | 同上 |
| `outbox/` | 沙箱投递渲染出来的 `.eml` 产物（[mail/transport.js:38-42](../server/src/mail/transport.js#L38-L42)），关掉沙箱真发信时不留这里 | 通常是可弃的 |
| `backup/` | `purge.mjs --purge-all` 清空前的自动快照目录（见 §8） | 自己按到期日清 |

### 备份（推荐：停服冷备）

库是单文件，但落盘产物在同目录的子目录里，所以最稳的做法是停服后整目录复制：

```bash
sudo systemctl stop awarelab
tar czf /backup/awarelab-$(date +%F).tar.gz -C /opt/AwareLab/server data config.yaml
sudo systemctl start awarelab
```

`config.yaml` 一起备：库没了还能重建，**后台路径与账号没了就找不回入口**。

备份文件含明文口令与明文证据，落盘位置和保留期按最敏感数据处理（加密盘、最小权限、到期删除）。
**不要把备份放在工程目录旁边**（更别放 `server/data/` 里）：`.gitignore` 把 `server/config.yaml`、`server/data/` 与任意位置的 `*.db` / `*.db-wal` / `*.sqlite`
都挡在仓库外了（[.gitignore:9-13](../.gitignore#L9-L13)、[.gitignore:26-31](../.gitignore#L26-L31)），**这条兜底就是给"备份/清理/迁移脚本意外落盘"留的**；
备份一旦落在仓库树里，一次 `git add -A`、一次打包分享、一次给外包开权限，就把演练数据送出去了。放仓库外、放加密盘、放最小权限的目录。

不能停服时用热备（SQLite 的 `VACUUM INTO` 出一份一致性快照，顺带把 WAL 里的内容折成紧凑单文件）：

```bash
node -e "const {DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('server/data/awarelab.db',{readOnly:true});d.exec(\"VACUUM INTO '/backup/awarelab-snapshot.db'\");d.close();console.log('ok');"
```

姿势与自检脚本完全一致：**先 `readOnly: true` 打开源库，再 `VACUUM INTO` 折出副本**（[server/scripts/selftest.mjs:55-64](../server/scripts/selftest.mjs#L55-L64)，注释就写着"历史库往往带着 WAL，直接复制文件会丢掉日志里的数据"）。
`readOnly` 不是可选项：它会趁早拦下"这库正被另一个实例占用"，而不是让你备出半份（同款理由见 [connection.js:89-95](../server/src/platform/storage/connection.js#L89-L95)）。
目标文件必须不存在，所以名字里带日期；反向的坑是同目录里别留一堆 `-wal`——自检脚本直接拒绝把 `-wal` 结尾的文件当种子（[selftest.mjs:73](../server/scripts/selftest.mjs#L73)），因为脱离主库的 WAL 单独复制出来读不懂。
热备只备库，落盘产物仍需另备。

> 顺带一个有用的行为：如果哪天库文件名换了，进程启动会按**文件头**认出目录里的前身 `.db`，用 `VACUUM INTO` 完整复制成新库，再把旧主文件与 `-wal` / `-shm` 一起改名成 `.bak-<时间戳>`，**绝不删除源文件**（[connection.js:41-93](../server/src/platform/storage/connection.js#L41-L93)）。
> 也就是说"历史库改名搬迁"是自动接上的，不用你手工导库；反过来说，别在数据目录里留多个 `.db`，它只搬按修改时间排最新的那一个。

### 恢复一台"库丢了"的环境

```bash
# 1) 停服
sudo systemctl stop awarelab
# 2) 把当前残骸挪开（不要直接删：先确认备份能用）
mv /opt/AwareLab/server/data /opt/AwareLab/server/data.broken
# 3) 解包备份（tar 里含 data/ 与 config.yaml）
tar xzf /backup/awarelab-2026-11-04.tar.gz -C /opt/AwareLab/server
# 4) 起服，看横幅
sudo systemctl start awarelab && journalctl -u awarelab -n 40
```

起服后逐条确认：

- `curl http://127.0.0.1:7778/alab/health` 返回 `ok`；
- 能用备份里的账号口令登录（登不上说明 `config.yaml` 没一起恢复）；连续输错会触发登录锁定，见 §11 的 `login_failures`；
- 「证据」工作区里历史记录条数与备份前一致；
- 「网站监听」里 `status=open` 的站点被自动恢复（横幅有 `已恢复 N 个`，[main.js:105-106](../server/src/boot/main.js#L105-L106)）；
- 授权仍在有效期内，否则建站与投递会被门禁挡住（403），被强制下线的站点要按 §6 的复服口径处理。

表结构不用手工管：进程启动时按 `PRAGMA user_version` 逐级补迁移，到位的版本直接跳过
（[server/src/platform/storage/schema.js:318-329](../server/src/platform/storage/schema.js#L318-L329)，调用点 [connection.js:112](../server/src/platform/storage/connection.js#L112)），
而且迁移**只加表、加可空列，禁止重命名既有列或改既有数据语义**（红线见 [schema.js:12-13](../server/src/platform/storage/schema.js#L12-L13)）。
所以拿旧版本的备份在新代码上恢复是安全的——它只会把缺的版本补上；**反过来（新库给旧代码用）不保证**，
旧代码读不懂新列之外的行为，而且任何一级迁移 SQL 抛错都会让进程直接起不来（结构半到位比起不来更危险，[schema.js:317](../server/src/platform/storage/schema.js#L317)）。
`PRAGMA foreign_keys` 虽然开着，但基线表都没写 `FOREIGN KEY` 子句，**级联清理全靠调用方显式 DELETE**，
别以为删父行会自动带走子行（[connection.js:108-110](../server/src/platform/storage/connection.js#L108-L110)）——手工修库时尤其要记得这点。

恢复后要不要清一遍：如果这台机器接下来还要跑新一轮演练，先 `node server/scripts/purge.mjs --status` 看过期数据，再决定 §8 的动作。

## 8. 数据保留期与清理（OPS-02）

### 自动清理

`exercise.retention_days > 0` 时注册定时器：**启动 30 秒后首跑，之后每 6 小时一次**，两个定时器都 `unref`，
不会拖住 `Ctrl+C` / `systemctl stop`（[server/src/platform/maintenance.js:38-41](../server/src/platform/maintenance.js#L38-L41)、[maintenance.js:406-409](../server/src/platform/maintenance.js#L406-L409)；
`retention_days <= 0` 时压根不注册，[maintenance.js:515-517](../server/src/platform/maintenance.js#L515-L517)）。
横幅会明确说启用与否（[server/src/boot/main.js:86-90](../server/src/boot/main.js#L86-L90)，未启用时的原因字符串来自 [maintenance.js:516](../server/src/platform/maintenance.js#L516)）：

```
数据保留期清理已启用（180 天，每 6 小时巡检一次）
数据保留期清理未启用：保留期未启用（演练数据与采集到的口令会一直留存）
```

第二行是刻意要让人看见的——"没配保留期"意味着明文口令只增不减，没人知道就等于没人负责。

清理范围是四张表 + 三个目录：`records` / `events` / `push_logs` 按数据保留期，`audit_logs` 按独立的审计保留期
（[maintenance.js:53-59](../server/src/platform/maintenance.js#L53-L59)）；文件只碰 `attachments` / `screenshots` / `outbox` 三个白名单目录，
**只删直接子层的普通文件**，符号链接跳过不删，绝不碰 `uploads`、绝不碰 `data` 根目录、绝不递归进未知子目录
（[maintenance.js:61-65](../server/src/platform/maintenance.js#L61-L65)、[maintenance.js:155-196](../server/src/platform/maintenance.js#L155-L196)）。
每次清理写两条 `data.prune` 审计（删前 `plan`、删后 `applied`，[maintenance.js:365-411](../server/src/platform/maintenance.js#L365-L411)），删过的东西只能靠审计自证；
`--dry-run` / 界面试算那条路径**一条审计都不写**（没发生的事不该留痕，[maintenance.js:384](../server/src/platform/maintenance.js#L384)）。
清理异常只打一行 `[maintenance] …` 日志，不把常驻进程带崩（[maintenance.js:400-402](../server/src/platform/maintenance.js#L400-L402)）。

### 接口

- `GET /maintenance/status`：保留期配置、两个 cutoff、各表待删行数、三个落盘目录的过期文件数、最老一条数据、下次巡检时间
  （[server/src/api/platformApi.js:305-308](../server/src/api/platformApi.js#L305-L308)，本体 [maintenance.js:447-490](../server/src/platform/maintenance.js#L447-L490)）。
  它每次都带 `withFiles: true` 真去扫目录并 `stat` 每个文件，**文件上万时会慢**，别拿去轮询；
  `next_sweep_at` 是从**最近一条 `data.prune` 审计**推算的"大概什么时候"，手动清一次会让它提前，不是承诺（[maintenance.js:467-477](../server/src/platform/maintenance.js#L467-L477)）。
- `POST /maintenance/run`：立刻跑一次，body `{"dry_run": true}` 只算不删也不写审计（[platformApi.js:310-323](../server/src/api/platformApi.js#L310-L323)）。
  手动清理会把审计的 `actor` 记成当前登录用户名、`ip` 记成来源，**追得到人**；定时器跑的那几轮才是 null。清理失败回 500 + 中文原因，不会被吞成 200。

> 截至本轮，前端还没把这两个接口接进「系统设置」（`web/src` 里搜不到调用点），日常运维请用下面的命令行；接口是给脚本与后续界面用的。

### 命令行 `server/scripts/purge.mjs`

脚本本体 [server/scripts/purge.mjs](../server/scripts/purge.mjs)，动作帮助文本用 `node server/scripts/purge.mjs --help` 就能打印（[purge.mjs:45-55](../server/scripts/purge.mjs#L45-L55)）；不带任何动作参数时按"参数不过"退出码 1（[purge.mjs:83-87](../server/scripts/purge.mjs#L83-L87)）。

```bash
node server/scripts/purge.mjs --status                    # 只读体检
node server/scripts/purge.mjs --sweep --dry-run           # 按保留期试算，不删不写审计
node server/scripts/purge.mjs --sweep                     # 按保留期真删（日常运维用这个）
node server/scripts/purge.mjs --purge-all --confirm=DELETE-ALL   # 演练收尾一键清空
```

三个动作的区别很重要，**选错就是删错**：

| 动作 | 删什么 | 备份 |
| --- | --- | --- |
| `--status` | 什么都不删（只有 SELECT + 目录 stat） | — |
| `--sweep` | 只删超过 `retention_days` 的行与文件（审计走独立保留期） | 不备份（有两条 `data.prune` 审计） |
| `--purge-all` | 不看时间，清掉一轮演练产生的 7 张表：`records` / `events` / `capture_tokens` / `mail_recipients` / `mail_tasks` / `push_logs` / `web_sites`（清单 [maintenance.js:72](../server/src/platform/maintenance.js#L72)） | **默认先 `VACUUM INTO` 到 `data/backup/purge-<时间戳>.db`**（[maintenance.js:435-452](../server/src/platform/maintenance.js#L435-L452)；同秒撞名会追加毫秒，备份写失败就**拒绝清空**，[maintenance.js:440-450](../server/src/platform/maintenance.js#L440-L450)） |

`--purge-all` 的可选参数（[purge.mjs:50](../server/scripts/purge.mjs#L50)）：`--no-backup`（不可回滚，别用）、`--files`（连 `attachments`/`screenshots`/`outbox` 一起清，
仍受"只删直接子层普通文件、路径必须在目录内"约束）、`--materials`（连 `learn_pages`/`web_templates`/`mail_templates` 一起清，
[maintenance.js:75](../server/src/platform/maintenance.js#L75)）、`--include-authorizations`（连授权记录一起清，**合规前提，默认保留**，
[maintenance.js:482](../server/src/platform/maintenance.js#L482)）、`--allow-running`（服务在跑时也清）。
`smtp_profiles` / `settings` / `sessions` **不在默认范围里**：清空的是这一轮演练的产物，不是平台自己的配置（[maintenance.js:69-72](../server/src/platform/maintenance.js#L69-L72)、[maintenance.js:41](../server/src/platform/maintenance.js#L41)）。

三条红线：

1. `--purge-all` 必须带 `--confirm=DELETE-ALL`（[purge.mjs:129-134](../server/scripts/purge.mjs#L129-L134)，比对常量 [maintenance.js:47](../server/src/platform/maintenance.js#L47)）。
   不做交互式 y/N——参数即承诺，脚本与自动化调用口径一致，也不会因为管道里没有 tty 而挂住；
2. `audit_logs` **永不在清空范围内**（[maintenance.js:458](../server/src/platform/maintenance.js#L458)）。清空动作本身要留痕，痕迹一起删就成了"发生过但没人知道"；
   这也是全仓唯一被允许 `DELETE FROM audit_logs` 的地方，理由只有磁盘与合规留存上限（[maintenance.js:13-14](../server/src/platform/maintenance.js#L13-L14)）；
3. 删掉的行不会关掉进程里正在监听的仿冒端口（监听归服务进程管，CLI 不起服务）。所以脚本会先探一次 `/alab/health`（800ms 超时，[purge.mjs:63-79](../server/scripts/purge.mjs#L63-L79)），
   **服务在跑就拒绝执行**，除非显式加 `--allow-running`（[purge.mjs:135-140](../server/scripts/purge.mjs#L135-L140)）——那时请自己负责"页面上线着、库里没记录"的现场。

想在副本上试：`AWARELAB_DATA=/path/to/copy AWARELAB_CONFIG=/path/to/copy/config.yaml node server/scripts/purge.mjs --sweep`。
不设这两个变量时，操作的就是 `server/config.yaml` 与 `server/data/awarelab.db`，也就是**生产数据**（[purge.mjs:17-19](../server/scripts/purge.mjs#L17-L19)）。
`data/backup/` 也已经在 `.gitignore` 里（[.gitignore:32-33](../.gitignore#L32-L33)），备份落在这里不会误入库，但**它同样是明文证据**，到期要删。

退出码：`0` 成功 / `1` 参数或前置检查不过 / `2` 执行期异常（[purge.mjs:27](../server/scripts/purge.mjs#L27)）。

## 9. 升级与回滚

```bash
# 升级

cd /opt/AwareLab && git pull
npm --prefix server install
npm --prefix web install && npm --prefix web run build   # 前端是构建产物，必须重新 build
```

三个容易踩的点：

1. **前端改了必须重新 `vite build` 并重启后端**：SPA 外壳在进程启动时读一次（[server/src/channels/adminPlane.js:34](../server/src/channels/adminPlane.js#L34)，注释同款提醒见 [server/src/boot/main.js:14](../server/src/boot/main.js#L14)），不重启就还是旧界面；
2. **表结构只加不改**：升级时按 `user_version` 自动逐级补迁移（[server/src/platform/storage/schema.js:318-329](../server/src/platform/storage/schema.js#L318-L329)），不需要手工 SQL，也不需要停库导出导入；加列迁移会先 `PRAGMA table_info` 探测再决定是否执行，重复启动是幂等的（[schema.js:17-18](../server/src/platform/storage/schema.js#L17-L18)）；
3. **回滚**：`git checkout <上一个 tag>` 后重复上面步骤。库若是新版本写过的（`user_version` 更高），
   旧代码读新列不会崩（新列只会是 NULL），但新功能写进去的数据旧界面看不见——所以回滚前先按 §7 备一份。

版本与变更记录见 [CHANGELOG](../CHANGELOG.md)；两端 `version` 必须一致（当前都是 1.2.0，[server/package.json:3](../server/package.json#L3)、[web/package.json:3](../web/package.json#L3)）；发布前必须过的门禁见 §10。
