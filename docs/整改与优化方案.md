## 1. 结论先说

**这个产品不是"没做完"，而是"没人管完"。** 核心闭环（拿授权 → 备素材 → 建钓鱼网站 → 发钓鱼邮件 → 查上钩记录 → 导出交付）代码级可用，沙箱优先、授权硬门禁、Host 准入三条合规约束真实落在服务端而不是写在文档里；164 条端到端断言可重复跑绿。

问题集中在**项目管控环节**：没有需求基线、没有版本与发布流程、没有审计（平台能记录员工的钓鱼行为，却记录不下"操作员自己干了什么"）、没有交付物包（缺 LICENSE / CHANGELOG / 部署运维手册 / 验收报告）、没有对真实业务场景的适配（无法按"一次演练"组织和交付证据）。

同时存在**必须先关的合规底线**：附件回传面无输入校验、管理面默认对全网卡开放并把明文口令打印到控制台、一键仿站会把目标域名发给任意第三方模型且服务端不校验授权、webhook 群机器人令牌被完整入库。

**处置方针：立足现有成品，不重写、不换栈、不改协议。** 用三个里程碑（合规底线 → 业务闭环 → 交付治理）把缺的环节补上，每一项整改都限定文件范围，并以现有测试矩阵作为回归门禁。预计 17 人日。

### 五维体检

| 维度 | 现状 | 判定 |
| --- | --- | --- |
| 功能完成度 | 闭环齐全，7 个工作区、双模编辑、一键仿站、观测大屏、CSV 导出均可用 | **合格**，可交付 |

## 3. 问题清单与分级整改方案

### 3.1 分级标准

| 级别 | 判定依据 | 处置要求 |
| --- | --- | --- |
| **P0 阻断** | 可造成越权采集、数据外泄、或让平台的合规前提（授权可追溯）失效 | 上线前必须关闭，不进入 M2 |
| **P1 高** | 影响证据可信度、核心业务闭环或授权方验收 | M2 内完成，验收必备 |
| **P2 中** | 影响运营效率、可维护性、交付完整性 | M3 内完成 |
| **P3 低** | 体验、规范、一致性 | 随 P1/P2 顺带处理，不单独排期 |

工作量单位为人日（1 人日 = 1 名熟悉本仓库的开发 + 自测）。

### 3.2 A 组 · 安全与合规

#### SEC-01 【P0】管理面默认全网卡开放 + 明文口令打印到控制台 + 无 HTTP 安全头

- **证据**：[server/src/platform/settings.js:33](../server/src/platform/settings.js#L33) 与 [server/src/api/siteApi.js:29,43](../server/src/api/siteApi.js#L43) 默认 `0.0.0.0`；[server/src/boot/main.js:22](../server/src/boot/main.js#L22) `config.panel.bind ?? '0.0.0.0'`；[server/src/boot/main.js:28-29](../server/src/boot/main.js#L28-L29) 每次启动把管理账号和**明文密码**打到 stdout；全仓库 grep `helmet|Content-Security-Policy|Strict-Transport|X-Frame-Options` **零命中**。
- **影响**：演示机/内网机上任何同网段的人都能访问后台并撞库；日志被集中收集时口令直接泄露；无 CSP 使采集页素材与后台页面缺乏 XSS 兜底。
- **整改（限定范围）**：
  1. `panel.bind` 默认改 `127.0.0.1`，放开到 `0.0.0.0` 需要在 `config.yaml` 显式书写并在启动横幅告警一次；
  2. 横幅不再打印口令，改为「口令见 config.yaml 的 panel.password；首次登录后请立即修改」；
  3. 管理面与信标面统一加 `Content-Security-Policy`（后台自用策略）、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff`；会话 cookie 加 `SameSite=Strict`，TLS 开启时加 `Secure` 与 HSTS；
  4. 采集端口 `listen_ip` 的默认值保持 `0.0.0.0`（**这是业务需要**，钓鱼页必须对外可达），但在站点列表和建站表单上标注"该端口对本机所有网卡开放"。
- **涉及文件**：`server/src/platform/settings.js`、`server/src/boot/main.js`、`server/src/channels/adminPlane.js`、`server/src/api/siteApi.js`（仅注释与校验）。
- **验收**：默认配置启动后 `curl 127.0.0.1:port` 可达、局域网 IP 不可达；启动输出与任何日志文件中不含口令明文（新增 e2e 断言 `stdout 不含 password`）；e2e 断言响应头存在。**1.5 人日**，低风险（纯默认值与响应头）。

#### SEC-02 【P0】附件回传面 `/alab/v2/callback` 无任何输入约束

- **证据**：[server/src/channels/beaconPlane.js:17](../server/src/channels/beaconPlane.js#L17) `multer` 内存存储、25MB 上限；[:93](../server/src/channels/beaconPlane.js#L93) `upload.any()` 接收任意字段；[:36-41](../server/src/channels/beaconPlane.js#L36-L41) `saveCapture()` 把任意字节流以 `<uuid>.png` 落盘；无 MIME 校验、无字段白名单、无按 token 的速率限制、无 token 时效校验（`records.form_json` 亦无长度上限）。
- **影响**：未持有有效 token 的人（token 会出现在邮件正文和链接里，转发即失效）可反复 POST 打满磁盘与内存（25MB × 并发 = 内存炸穿），也可把本平台当作免费文件落地点。这是**平台被反用作攻击基础设施**的现实路径，与"仅供授权演练"的定位直接冲突。
- **整改（限定范围）**：
  1. 字段白名单：只接受 `capture` 一个文件字段 + 该站点模板已声明的表单字段名，其余丢弃并记 `events`；
  2. 文件约束：MIME ∈ {png, jpeg, pdf, zip}，单文件 ≤ 5MB，单次请求 ≤ 3 个文件；扩展名与真实 magic bytes 双重校验；
  3. token 校验升级：必须命中 `capture_tokens` 且 `expires_at` 未过、该 token 未关闭；
  4. 速率限制：按 token 与按 IP 双维度，超过阈值返回 429（复用现有 `tooManyRequests`）；
  5. 落盘目录加配额巡检，超限时拒绝并提示操作员清理。
- **涉及文件**：`server/src/channels/beaconPlane.js`、`server/src/capture/evidenceStore.js`（写入前的字段过滤）。
- **验收**：新增 e2e 用例 ≥ 5 条 —— 伪造字段名被丢弃、非白名单 MIME 拒收、无 token / 过期 token 拒收、并发 20 次第 N 次起 429、落盘文件 magic bytes 正确。**2 人日**，中风险（不能破坏现有 164 条里的附件回传用例，需同步更新 e2e）。

#### SEC-03 【P0】一键仿站把目标域名发给任意第三方模型，服务端不校验授权

- **证据**：[server/src/api/platformApi.js:101-108](../server/src/api/platformApi.js#L101-L108) 直接把 `provider.base_url` 拼成请求地址、带上 `api_key` 发出去；目标站点名/字段随 prompt 外发；授权校验只存在于前端提示 [web/src/workspaces/material/ClonePane.vue:39](../web/src/workspaces/material/ClonePane.vue#L39)（一句软文案，不是拦截），服务端无 `assertDeployment` / `isDomainCovered` 调用。
- **影响**：操作员可以在**没有任何授权登记**的情况下，把"要仿冒哪个域名"这件事告诉外部第三方模型 —— 授权硬门禁被一条侧路绕过，且泄露了演练计划（属于敏感信息）。这是合规前提被破坏，不是普通 bug。
- **整改（限定范围）**：
  1. 仿站入口调用前强制 `findActive()` + `isDomainCovered(auth, targetHost)`，越界返回 400 并沿用 [server/src/security/mandate.js:90](../server/src/security/mandate.js#L90) 的既有文案「访问用的域名 … 不在授权名单内，已拒绝服务。」；
  2. `provider.base_url` 强制 https，且必须是操作员显式保存过的地址（不接受请求里临时传入的 URL）；
  3. prompt 只包含**页面结构与字段语义**，禁止把真实员工邮箱、站点端口、任务 ID 带入外发请求；
  4. 前端把"请确认目标在授权名单内"的软提示改成失败即展示服务端拒绝原因。
- **涉及文件**：`server/src/api/platformApi.js`、`server/src/security/mandate.js`（复用，不改逻辑）、仿站面板。
- **验收**：未授权状态调用仿站返回 400（e2e 新增）；授权名单外域名返回 400；抓包/日志断言外发 body 不含邮箱与端口。**1 人日**，低风险。

#### SEC-04 【P0】完全没有操作审计 —— 平台记录员工，不记录操作员

- **证据**：14 张表（`sqlite_master` 实测）**无审计表**；[server/src/api/mandateApi.js:31,37,45](../server/src/api/mandateApi.js#L31-L48) 授权登记/续期/吊销不记录操作人，且 `authorizations` 表根本没有 `updated_at` 列（`PRAGMA table_info` 实测只有 `created_at`），改了窗口也看不出是什么时候改的；关闭沙箱（`dry_run` 1→0）、导出证据、删除上钩记录、改运行参数同样无痕；`req.session` 只在 whoami 里被读过一次；[server/src/api/evidenceApi.js:124-127](../server/src/api/evidenceApi.js#L124-L127) 用 `push_logs`（本来是外发通知日志，见 [schema.js:174-182](../server/src/platform/storage/schema.js#L174-L182)）冒充审计，且只存 IP 不存用户名。
- **影响**：一旦演练数据被质疑（"这条记录是不是演练之后被人改过？""谁把沙箱关了真发的邮件？"），平台**拿不出任何自证材料**。对合规红队工具而言这是致命缺陷 —— 授权方要的不仅是员工上钩证据，还有"你们平台的操作是否在我授权范围内"。
- **整改（限定范围，不动既有表）**：
  1. 新增第 15 张表 `audit_logs(id, actor, action, target_kind, target_id, detail_json, ip, created_at)`，只增不改不删；
  2. 提供 `writeAudit(req, action, target, detail)` 单一助手，接入 6 类高危动作：授权登记/续期/吊销、`dry_run` 变更、任务真实发送、证据导出、证据/站点删除、运行参数变更；
  3. `push_logs` 回归"外发通知日志"单一职责，把 [evidenceApi.js:123](../server/src/api/evidenceApi.js#L123) 的注释兑现成真实审计；
  4. 后台「上钩记录 · 通知记录」旁增加「操作审计」只读页（不新增工作区，避免冲击刚定稿的信息架构）；
  5. 授权的"什么时候被改成什么窗口"由 `audit_logs` 逐条回答（含操作人、IP、变更前后值），不新增 `updated_at` 列 —— 见 8.5 偏差 D4。
- **验收**：跑一遍"登记授权 → 建站 → 关闭沙箱 → 真实发送 → 导出 CSV → 吊销授权"，`audit_logs` 恰好人眼可读地落 6 条以上，每条含用户名 + IP + ISO 时间；现有 e2e 全绿（审计失败绝不影响主链路，写审计包 `try/catch`）。**2 人日**，低风险（新表 + 新写入点）。

#### SEC-05 【P0】webhook 外发内容含员工邮箱，且群机器人令牌明文入库

- **证据**：[server/src/capture/evidenceStore.js:108,148,164,198](../server/src/capture/evidenceStore.js#L148) 推送文本包含 `目标=真实员工邮箱`、站点/任务 ID、OS/浏览器，以及**提交的表单字段名**（`Object.keys(fields)`，字段**值**不外发 —— 口令本身不发，这点是好的）；[server/src/notify/notifier.js:19,37](../server/src/notify/notifier.js#L19) 把完整 `url`（钉钉/企微/飞书机器人令牌就在 query 里）与 body 一起写进 `push_logs`；[server/src/api/platformApi.js:73](../server/src/api/platformApi.js#L73) `setSetting(key, incoming)` 对推送 URL 无协议/域名校验。
- **影响**：① 员工上钩这一敏感事实被推送到第三方 IM 群，群成员范围由操作员自控但平台不做任何约束与脱敏选项；② 机器人令牌泄露 = 任何人可向该企业群发消息；③ `push_logs` 长期留存等于把历史敏感 payload 堆在库里。
- **整改（限定范围）**：
  1. `push_logs.request` 落库前对 URL 做掩码（保留 host + path，query 中的 `access_token/key/signature` 一律替换为 `******`，复用现有 `SECRET_MASK`）；
  2. 推送文案新增开关「脱敏推送」，默认开启 —— 开启时把 `目标=` 替换为不可逆短哈希（前 8 位），字段名列表改为字段数量；
  3. 保存推送渠道时校验：必须 https、host 命中已知机器人域名白名单，并在 UI 提供「发送测试消息」预览最终文本；
  4. `push_logs` 加保留期（默认 90 天）并纳入 OPS-02 清理任务。
- **验收**：触发一次真实提交后，DB 与出口日志中均查不到明文令牌与完整邮箱；关闭脱敏时页面出现明确风险告知。**1.5 人日**，低风险。

#### SEC-06 【P1】管理面只有一道口令

- **证据**：[server/src/security/session.js:9-15](../server/src/security/session.js#L9-L15) 失败计数只在内存，重启即清零（注释明说）；[schema.js:167-172](../server/src/platform/storage/schema.js#L167-L172) `sessions` 只有 token/username，无 IP、UA、签发来源；无"吊销全部会话"入口；改口令后旧会话继续有效；无二次验证。
- **影响**：撞库成功即获得全部演练数据与发信能力；口令修改不构成有效撤销。
- **整改**：失败计数落 DB；`sessions` 增列 `ip / user_agent / created_ip`（新列允许为空，不迁移历史语义）；「系统设置」增加「退出所有会话」按钮；`panel.password` 变更即清空 `sessions`；`config.yaml` 新增可选 `panel.allow_ips` 白名单。二次验证（TOTP）列为 P3，本期不做，理由见第 4 节。
- **验收**：改口令后旧 token 立即 401；重启后失败计数仍生效（e2e 断言）。**1.5 人日**。

#### SEC-07 【P1】HTML 全程无净化 + 口令明文入库且无保留期

- **证据**：[web/src/components/RichEditor.vue:63-86](../web/src/components/RichEditor.vue#L63-L86) 富文本与 HTML 双向 `innerHTML`，全仓库 grep `DOMPurify|sanitize` 零命中；[schema.js:137](../server/src/platform/storage/schema.js#L137) `records.form_json` 原文存放采集到的口令；grep `retention|prune` 零命中。
- **影响**：邮件正文渲染是天然 XSS 面（操作员素材来自一键仿站与外部导入）；采集数据永久堆积且包含明文口令。
- **整改（注意：口令明文是演练证据的核心，不能擅自删）**：
  1. 引入 `DOMPurify`，只对**预览与教学页渲染**做净化；仿站素材保存时保留原文（证据需要）；采集页运行时改用 `sandbox` iframe 预览；

## 6. 回归门禁（每次整改必须过）

2026-11-05 起，下表 1–6 步与第 8 步收进一条命令：`node server/scripts/ci.mjs --with-smoke`（八步：语法 / lint / 前端构建 / 自检含 e2e / QA / 种子回归 / 依赖审计 / 实机冒烟，任一步失败即非零退出）。**第 7 步界面走查仍是人工**——QA-22（8.10）证明"模板里引了脚本没有的绑定"这类缺陷机器三关都不报。

| 步骤 | 命令 | 通过标准 |
| --- | --- | --- |
| 1 隔离自检 | `node server/scripts/selftest.mjs` | 在全新隔离副本 + 独立端口上通过，**绝不触碰生产库** |
| 2 端到端 | 由步骤 1 拉起 `e2e.mjs` | 与自检合计 246 条判定全绿（M1 结束时 195，QA 轮 208，M2/M3 新增断言后 246）；文案断言与后端字符串同步（改名轮踩过：`白名单` → `授权名单`；QA 轮又踩过：访客侧文案中性化后，断言不能再要求页面**包含**「授权名单」） |
| 3 QA 四维用例 | `node server/scripts/qa.mjs` | 86 条全绿（安全 32 / 功能 23 / 流程 15 / 人性化 16）；明细与实测证据落 `server/.qa/qa-result.json`，用例清单见 [测试用例.md](测试用例.md) |
| 4 种子回归 | `E2E_SEED=data/awarelab.db node server/scripts/selftest.mjs` | 用生产库**只读副本**（`VACUUM INTO`）起步，验证表结构迁移在真实数据上可加不丢数据（当前到 v6）；遇到非本脚本登记的生效授权时相关用例判 SKIP，不许抢跑 |
| 5 冒烟（只读） | `node server/scripts/smoke.mjs` | 24 项，允许因"当前无开启站点"产生 skip，不允许 fail |
| 6 前端 | `npm --prefix web run build` | 无 error；lint 作为独立一步拦未使用变量与无用赋值；构建后**必须重启后端**，壳页是启动时一次性读取的 |
| 7 界面走查 | 浏览器逐页检查受影响工作区 | 文案、按钮、空状态、错误提示符合预期（注意：本环境截图不可用，Vue 输入需派发原生 `input/change` 事件才生效）；新增的界面交互必须登记成走查用例，见 [测试用例.md](测试用例.md) §10.3 |
| 8 只读复核 | `node:sqlite` + `readOnly: true` 探针 | 表数、行数、状态分布符合预期；写测试一律在隔离副本执行 |

**准出规则**：整改项与它的新增断言必须同一个变更单元提交；只改代码不加断言的 P0 整改不予验收。凡"只有界面才有"的控制点（确认闸门、掩码查看、批量标记），除接口断言外还要登记一条界面走查用例。

### 8.6 缺陷记录 DEF-01（2026-11-04 · 手工测试发现，已闭环）

**现象**（业主手工测试）：建好钓鱼网站 → 生成专属链接 → 打开填写并提交 → 「上钩记录」里只有打开，没有提交。

**根因**（实测生产库，非推测）：站点 `212d7822`（:8080）挂的模板「账号安全核验」把提交写成 `<input type="button" value="立即核验" onclick="login()">`。`type="button"` 不触发 `submit` 事件，页面又没有 `data-al-collect` 声明，运行时两条采集路径都没走到；`login()` 在模板里根本没有定义，点击只剩一次 `ReferenceError`。证据侧同一令牌只有 `page_open` 事件、没有 `form_fill`，与结论一致。

**这是旧版约定的坑**：早期那套做法要求页面自己写采集代码，换成声明式协议后老模板没人补显式提交控件，就出现"点了没留痕"。

**处置（三层，都不改生产数据）**

| 层 | 改动 | 文件 |
| --- | --- | --- |
| 采不到 → 采得到 | 运行时加兜底：表单内既无提交控件又无 `data-al-collect` 时，把表单里的按钮当提交接管（捕获阶段先于内联 `onclick`，页面自带脚本报错也不影响采集）；提交上报改 `keepalive`，避免老模板点完立刻跳转把请求取消 | [capture/engageScript.js](../server/src/capture/engageScript.js) |

**本轮定下的口径（方案里没写，落地时必须统一）**

- **教育覆盖率 = （已教育 + 已关闭）/ 上钩记录总数**；"已联系但未完成教育"计入处置率、不计入覆盖率。界面注释、按授权汇总与交付报告三处同一算法。
- **迁移只加列不回填**：v6 之前老行的 `disposition` 是 NULL，筛选"未处置"时后端连带命中 NULL，视图侧把 NULL 归一成 `new`——否则历史数据在看板上凭空消失一批。
- **审计比它记录的证据活得久**：`audit_logs` 用独立的 `audit_retention_days`（365）而不是 `retention_days`（180），`--purge-all` 永不删审计。
- **白名单外的请求回 404 不回 403**：403 等于告诉扫描器"这里有后台，只是不让进"。

**与方案的偏差（5 项，需业主确认是否加严）**

- **G1｜验证脚本没有迁到仓库根的 `tools/`**（GOV-04 的一项）。它们互相引用、还要以 `server/src` 为工作目录起子进程，搬走只会给每个路径加一层 `../`。替代做法：CONTRIBUTING 里明确"脚本目录 = 只碰隔离实例与只读副本，禁止连生产库"。
- **G2｜没有独立的「验收报告.md」**。再做一份就是把测试报告复制一遍，两份迟早分叉；改为在报告 §9.5 写清"能不能上线"的结论与残余风险，由本节 §5 的 DoD 自评配套。
- **G3｜OPS-01 的 DoD「按文档从零部署一次成功」只实测到一半**。跑通的是"复制 `config.example.yaml` + 空数据目录 + 独立端口起实例"这条路径（隔离实例每轮都这么起）；systemd / Windows 服务化、以及"库丢了"的完整恢复演练**没有在本机实跑**——本机没有 Linux，恢复演练要动生产库。文档按"可照抄"的标准写，但执行证据要部署者回填。
- **G4｜BIZ-02 的确认仍是客户端闸门**。服务端 `POST /mail-tasks/:id/send` 的把关还是授权、任务存在、名册非空三项，绕开界面直接调接口可以在没有确认的情况下真发信。要给接口加显式确认字段是一次接口变更（协议与用例都要同步），等业主裁决，见 [测试报告.md](测试报告.md) §9.5 R-06。
- **G5｜两类预览的 `sandbox` 口径不同是有意的**：仿站素材预览给 `allow-scripts allow-forms allow-modals allow-popups`（不给 `allow-same-origin`），因为素材要能跑出交互才看得出效果；教学页预览用 `sandbox=""` 全禁。别把它们"顺手统一"。
