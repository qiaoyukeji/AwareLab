## 1. 结论先说

平台在这轮之前**不是不能用，而是会静默说谎**：改到一条不存在的记录它回成功，一封都没发出去它标成「已发送」，访客页面上写着「该演练站点未处于开启状态」。前一类让操作员基于错数据做决定，后一类当场把演练作废——对钓鱼演练平台来说，这两类都是要命的。

本轮做完的三件事：

1. **建立第四层测试**：原有 e2e/自检只回答"接口通不通"，新增的 `qa.mjs` 按安全 / 功能 / 流程 / 人性化四维出题，73 条，且把"演练对象看到的文案"变成机器断言，不再依赖人眼。
2. **修掉 5 个可被真实利用的安全缺陷**，最重的是伪造一个请求头就能绕过登录失败锁定，和授权域名用后缀匹配导致 `evil-example.com` 被顺带放行。
3. **补齐人性化缺口**：时间不再按 UTC 显示、风险分不再拖着浮点尾巴、兜底学习页不再只喊一句"请提高安全意识"。

**能不能上线？** 从测试口径看可以：四个执行器全绿，生产库上的升级路径（迁移 v4）已在只读副本上验证，现网冒烟 24 项 0 失败。但下面 §6 的 5 项残余风险需要业主知情，其中 DEF-01（老模板只有动作按钮没有 `<form>`）是唯一还需要拍板的产品裁决。

### 2.1 两处 SKIP 是保护，不是遗漏

- 种子回归的 3 项（「无授权时拒绝建站」等）会**吊销授权**来验证级联下线。副本里带着现网那条仍在生效的授权，脚本一旦跑这三条就会把操作员正在进行的演练停掉，于是判定为 SKIP。宁可少跑三条，不能碰真实演练。
- 冒烟的 1 项是现网确实还没登记发信邮箱，断言无处可验。

## 7. 安全专项结论

按四类控制点复核，均有机器断言：

1. **授权硬门禁**：5 类投放动作（建站、开站、签链接、发信、一键仿站）在无生效授权时全部 403 且文案指向「演练授权」；收网不受门禁影响；出窗口级联下线，续期只复服平台强制下线那批。
2. **会话与来源可信性**：令牌 + Cookie 双入口、到期与登出即时作废、Cookie 属性齐备；锁定按不可伪造的 socket 对端计数，阈值 8 次 / 10 分钟窗口，成功后清零。
3. **凭据与隐私**：TLS 私钥与 SMTP 口令永不出现在响应与审计里，推送令牌掩码，脱敏开关实测生效（开时不含员工邮箱，关时按操作员意愿回原文）。
4. **输入闸门**：管理面 8MB、采集面上报 512KB、回传单文件 5MB / 3 文件 / 40 字段，同令牌每分钟配额，越界不解析；XSS 载荷在存储、检索、导出、预览四个出口都保持惰性；注入式查询参数不改语义、不动表结构。

**明确不做的能力**（与产品红线一致，本轮未引入）：反检测与反溯源、凭据转发到第三方、规避网关的载荷生成。

### 9.3 全流程走查记录（隔离实例，逐屏）

一次性实例用 `AWARELAB_CONFIG` / `AWARELAB_DATA` 指到系统临时目录，端口 7798、采集 8321/8322，与现网 7778 完全隔离；跑完吊销授权、清掉临时目录。

- **采集面（含 DEF-01）**：建一张只有 `<button type="button">` 的模板（无 `<form>` 提交控件、无 `data-al-collect`），站点诊断分 75（提交触发点扣 25）而非 100。生成专属链接 → 浏览器打开 → 填账号口令 → 点按钮。结果：`capture_tokens.submitted_at` 有值、`events` 落 `page_open` + `form_fill`、`records` 生成网页记录，上钩记录看板这一组显示「上钩终端 1 / 页面打开 1 / 已提交 1 / 提交率 100%」，采到的字段列出 `account`、`secret`。**运行时对老式动作按钮的兜底确实能采集**，业主的保留/移除裁决仍悬着（§6 DEF-01）。
- **掩码与留痕**：详情里 `secret` 默认圆点掩码，点「显示明文」才出原值，随即写一条 `record.secret_reveal` 审计（`detail` 只有字段名与类型，不含值）。
- **投递面**：沙箱任务点发送不进确认弹窗，直接落 `.eml` 并提示「沙箱发送完成 N 封」；把同一任务拉到真发后点发送进弹窗，取消后审计里没有新的 `real_send`（本轮取消，未真的寄信）。
- **交付件**：「生成报告」新标签页里时间与状态都是人话、承诺条款在页上；「导出交付CSV」表头 10 列中文、口令列 `••••••••`、邮箱列 `t***@corp.example`、含处置状态列。
- **授权级联**：在「演练授权」点吊销 → 高危确认框（写明确实会停掉其下所有监听）→ 确认后界面转「无有效授权」并说明拒绝范围，`web_sites` 两行落 `closed`，8321/8322 端口连接被拒，审计记 `revoked`。硬门禁端到端成立。

### 9.4 工装自己的问题（不是产品缺陷）

| 现象 | 真实原因 | 处理 |
| --- | --- | --- |
| 往收件人框里填文本后导入，服务端回「新增 0，格式非法 0」 | 探针 `querySelector('textarea')` 命中的是富文本编辑器那个**隐藏**的 HTML 源码框，把正文改了（没点保存，库未受影响） | 选择器加可见性与 placeholder 判据；这条也说明界面上同屏存在两个 textarea，人也容易点错 |
| 确认弹窗探针返回空列表 | 那是 `el-message-box`（`.el-overlay.is-message-box`），不是 `.el-drawer` / `.el-dialog` | 覆盖层统一按可见性与类名集合筛 |
| 报告样本里出现 `û` 一类乱码字段名 | Windows 控制台用 GBK 发 curl 请求体，不是产品解码问题（中文附件名与中文字段名由 TC-P-04 走真实 UTF-8 multipart 验证） | 记为工装口径，不改产品代码 |
| 把 `ci.mjs` 接管道后退出码变 0 | bash 取的是管道最后一个命令的状态，`tail` 永远 0 | 门禁一律重定向到文件再看 `CI_EXIT` |

**一处工具链缺口要写出来**：`el-dialog` 那种「模板引用了脚本里没有的绑定」，构建、lint、`node --check` 都抓不到——`vue-eslint-parser` 不把模板表达式交给核心 `no-undef`，本项目实测确认如此（临时加规则跑探针，未定义标识符 0 报错）。要堵这一类，只有上 `vue-tsc` 或在 CI 里加一条真正挂载组件的检查，本轮按现状记下，不改动门禁口径。
