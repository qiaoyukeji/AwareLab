# 术语对照表

> 给谁看：甲方安全负责人、乙方操作员、接手代码的程序员、测试与值班同学。
> 这个平台刻意把**界面文案做成大白话**（「钓鱼网站」「上钩记录」），而代码与协议里保留工程术语
> （「采集面」「信标面」「mandate」）。跨角色沟通时两边说的常常不是同一个词——本表就是把话对上。
>
> 三个口径的来源都是代码，不是本文的约定：界面名取自 `web/src/router/index.js` 与工作区标签页，
> 代码标识取自 `server/src/`，协议字段以应用内「系统设置 · 协议文档」为唯一权威。
> 改了名字请同步改这张表（CONTRIBUTING 的「界面文案面向操作员」条目）。

## 1. 七个功能区的对照

| 界面叫法 | 工程/专业名 | 代码里的标识 | 一句话解释（给甲方） |
| --- | --- | --- | --- |
| 演练总览 | 看板 / dashboard | `console` · `ConsoleWorkspace` · `insightApi` | 一眼看到这次演练有多少人中招、趋势如何 |
| 演练授权 | 授权门禁 / mandate | `mandate` · `mandateApi` · `security/mandate.js` | **没有这里登记的有效授权，平台不给干活** |
| 钓鱼素材 | 素材库 / material | `material` · `pageApi` · `lessonApi` | 假登录页、邮件文案、教学页都在做准备 |
| 钓鱼网站 | 采集面 / capture plane | `capture` · `siteApi` · `capture/siteRegistry.js` | 每个假页面占一个端口，专门收访客提交的内容 |
| 钓鱼邮件 | 投递面 / outbound | `outbound` · `campaignApi` · `mail/campaignRunner.js` | 把邮件发出去；默认在沙箱里，不真发 |
| 上钩记录 | 证据链 / evidence | `evidence` · `evidenceApi` · `capture/evidenceStore.js` | 谁打开、谁提交、提交了什么 |
| 系统设置 | 平台配置 / platform | `platform` · `platformApi` · `platform/settings.js` | 运行参数、协议文档、会话与审计入口 |
| 观测视图 | 大屏 / bigscreen | `/screen` · `ScreenView.vue` · `/stats/bigscreen` | 挂在墙上的滚动看板，不是操作界面 |

## 2. 高频界面词 → 真实含义

| 界面文案 | 背后是什么 | 位置 |
| --- | --- | --- |
| 上钩 / 中招 | 访客打开了假页面或提交了表单 | `records` 表，`kind` 与 `events.kind` |
| 专属链接 | 带令牌的采集入口，一人一条 | `capture_tokens` 表；链接里的 `tk` 参数 |
| 令牌（token） | 访客身份凭据，32 位随机串 | cookie `alab_token`（后台会话另有一套，见 §4） |
| 已打开页面的终端数 | 按访客令牌去重后的设备数 | 不是一个邮箱一条，同一人重复打开只算一台 |
| 停留时长 | 首次打开到最后一次活动 | `records.dwell_seconds` |
| 转化率 | 提交数 ÷ 打开数 | 看板的 `conversion` |
| 沙箱 | 邮件只落本地 `.eml` 文件，不真发 | `mail.default_dry_run` / 任务的 `dry_run` |
| 真实发送 | 真的往邮箱投递 | `dry_run=false`，界面需手输收件人数确认 |
| 拉回沙箱 | 立刻停止真实发信 | 任务上的刹车按钮，任何时刻可用 |
| 处置状态 | 这条上钩记录后续跟到哪一步 | `records.disposition`：未处置 / 已联系 / 已教育 / 已结案 |
| 教育覆盖率 | （已教育 + 已结案）÷ 上钩记录总数 | 总览看板卡片；分母是记录数，不是人数 |
| 收网 | 关闭某个钓鱼站点的监听 | 站点 `status=closed` + `close_reason='manual'` |
| 授权到期强制下线 | 平台替你把站点掀了 | `close_reason='authorization'`，续期后自动复服 |
| 通知记录 | 群机器人推送的流水 | `push_logs`（失败不影响采集） |
| 操作审计 | 操作员自己动过什么的流水 | `audit_logs`，只增不改不删 |

## 3. 采集协议 v2 的字段与命名由来

| 协议标识 | 中文说法 | 由来与注意 |
| --- | --- | --- |
| `alab` | 产品前缀 | **A**ware**Lab** 的缩写，用于路径、头名与 cookie 名的命名空间；与被研究过的任何同类产品无关，是本平台的独立命名 |
| `/alab/health` | 体检接口 | 公开、无鉴权，只回答"平台活着" |
| `/alab/v2/engage` | 提交入口 | 访客在假页面点提交后，采集运行时把字段 POST 到这里；`v2` 是协议主版本，与产品版本独立编号 |
| `/alab/v2/lesson` | 教学页跳转 | 提交后把访客送到教育页 |
| `/alab/v2/pixel` | 邮件打开回执 | 1×1 透明图，邮件客户端加载即记账 |
| `/alab/v2/trace` | 链接点开回执 | 邮件里每条专属链接的跳转，先记账再放行 |
| `/alab/v2/callback` | 附件回传 | 无害化说明性载荷回报运行状态与截图，按"演练证据"而非"文件托管"约束（MIME/大小/频率三重闸门） |
| `x-alab-token` | 会话令牌请求头 | 后台管理面的会话凭据，登录后签发 |
| `alab_token` | 会话 cookie | 上面那个头的 cookie 形态，`SameSite=Strict` |
| `alab_tk` | 访客 cookie | **给演练对象**的采集令牌，与会话 cookie 完全两码事，别混 |
| `tk` | 链接里的令牌参数 | 专属链接上的查询参数，签发时写入 `capture_tokens` |
| `ev` | 事件类型 | 取值只有 `open`（打开）与 `submit`（提交） |
| `<script type="application/alab+json" id="alab-boot">` | 启动配置块 | 采集运行时不靠页面自带脚本，配置以 JSON 块随页面下发；`id` 与 `type` 都被 e2e 断言锁定 |
| `data-al-collect` | 采集声明 | 模板里标了这个属性的表单才参与采集（声明式，取代早期"页面自己写 onclick 提交"的约定） |
| 承诺原文（pledge） | 使用承诺 | 登记授权时的合规声明，界面用一次勾选确认，原文原样入库 |

> 旧约定永不回归：页面自写 `onclick="login()"`、厂商私有会话头、私有内部路径。
> 看到代码或文档里出现这类字样，按 CONTRIBUTING 的规矩直接关掉那个 PR。

## 4. 容易混的三对概念

| 看起来一样 | 实际不同 |
| --- | --- |
| `alab_token` vs `alab_tk` | 前者是**操作员**登录后台的会话凭据；后者是**演练对象**浏览器上的采集令牌。泄露前者=后台被进，泄露后者=某人上钩记录被串到别人身上 |
| `push_logs` vs `audit_logs` | 前者是"往群里推了什么"（外发通知，可掩码可清理）；后者是"操作员干了什么"（自证材料，只增不改）。早期版本曾用前者冒充审计，已修正 |
| 授权（authorization） vs 演练项目 | 平台没有独立的"演练项目"表：一次授权 = 一次演练的锚点，站点与任务都挂在 `authorization_id` 上；「按授权汇总」就是按演练出报告 |

## 6. 运维口头术语

| 说法 | 指的是 |
| --- | --- |
| 三张面 | 管理面（后台）/ 采集面（每站一个端口）/ 信标面（公开回执），同一个进程里 |
| 后台随机路径 | `config.yaml` 的 `panel.path`，32 位十六进制；挡扫描器用，不是鉴权，也不是口令 |
| 出厂口令 | 首次启动随机生成并写进 `config.yaml` 的那串；`panel.password_updated_at` 缺失表示还没改过 |
| 保留期 | `exercise.retention_days`（证据）与 `exercise.audit_retention_days`（审计），到期由清理任务删除并留审计 |
| 隔离副本 | 验证用的独立数据目录与端口（`server/.selftest`、`server/.qa`），**绝不允许**对着 `server/data` 写 |
| 只读探针 | `scripts/smoke.mjs`：对正在跑的实例做体检，不建站不发信不写库 |
