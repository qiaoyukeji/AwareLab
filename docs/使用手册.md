# AwareLab 用户操作使用手册

本手册面向演练操作员，按"登录 → 登记授权 → 备素材 → 建钓鱼网站 → 发钓鱼邮件 → 查上钩记录 → 导出与收尾"的实际动作顺序编写。文中带「」的文字是界面上的原文标签、按钮或提示，可直接对照寻找。

---

## 0. 先读这一页：本平台的边界

AwareLab 是**安全意识演练**工具，不是攻击工具。它的设计前提是你手上已经有一份授权文件。

- 平台内置**授权硬性要求**：没有生效的授权记录时，建站和发送一律被服务端拒绝，返回「当前无有效演练授权，请先在「演练授权」中登记授权范围与有效期。」
- 演练授权的开关 `exercise.require_authorization` **在管理界面里关不掉**，只能在 `server/config.yaml` 改。界面上只会显示 chip「授权硬性要求：开启」或「授权硬性要求：已在配置文件中关闭」。
- 邮件**默认沙箱发送**（不落网络，只生成 `.eml` 文件供人工复核）。真实发信需要在任务里显式关掉「沙箱模式」，界面会立刻亮出红条「风险提示：真实发信已开启」。
- 刻意**不实现**的能力：反溯源与反检测、把采集到的凭据实时转发给第三方、免杀载荷生成。这些能力不存在，也不会有。
- 不要把本平台部署成公网可达的服务。管理面默认**只监听 127.0.0.1**（`panel.bind`），随机路径**不是鉴权，只是降噪**，真正的准入是登录会话；钓鱼网站靠 Host 授权名单 + 演练令牌。
- **访客侧的两个公开入口自带闸门**：采集面单次上报体上限 512KB；附件回传面 `/alab/v2/callback` 只认这次演练发出去的令牌（陌生令牌 400、授权窗口关闭 410），文件只收 png / jpeg / pdf / zip 且必须文件头与扩展名自洽，单文件 5MB、单次最多 3 个文件、40 个字段，同一令牌每分钟 10 次、同一来源 IP 每分钟 200 次，超出返回 429。平台收的是演练证据，不是任何人想塞进来的文件。

## 1. 启动与登录

### 1.0 最省事的方式：双击 exe（Windows）

如果拿到的是 `AwareLab.exe`，不用装 Node、不用开命令行：双击即可。它会在自己旁边建 `AwareLab-data/`，首次启动生成配置、初始化数据库、解包前端，然后自动打开浏览器到管理端。**关掉那个黑色窗口就是停服**。

- 口令在 `AwareLab-data/config.yaml` 的 `panel.password`，窗口里只打印账号。
- 目录不可写（例如放进 `Program Files`）时，数据会落到 `%LOCALAPPDATA%\AwareLab`。
- 端口被占用时不会一闪而过：窗口会列出占用进程（名称、PID、路径、命令行），并问一句是否结束它；输入 `y` 就释放并继续启动。无人值守场景不弹问题，按提示 `taskkill` 或改 `panel.port`。exe 的数据目录在 `AwareLab-data/`，改的是那里面的 `config.yaml`。
- 想自定义位置，先设环境变量 `AWARELAB_HOME=<目录>` 再双击。

下面 1.1 / 1.2 是源码运行方式，适合要改代码或接 CI 的场景。

### 1.1 后端

```bash
cd server
npm start          # 生产启动（node src/boot/main.js）
npm run dev        # 带 --watch，改代码自动重启
npm test           # 端到端自测（隔离数据副本 + 独立端口，不碰你的真实数据）
```

首次启动如果 `server/config.yaml` 不存在，会自动生成一份，并**随机**产生后台路径与管理员口令。启动横幅形如：

```
AwareLab 安全意识演练平台
本工具仅可用于授权范围内的安全意识演练。
数据库驱动: sqlite

管理后台: http://127.0.0.1:7778/<32位随机路径>/
账号: <panel.username>
密码: 见 config.yaml 的 panel.password（登录成功后建议立即更换）

连通性自检: http://127.0.0.1:7778/alab/health
已恢复 N 个演练站点监听
```

**口令不再打印在横幅里**：启动输出会被 `nohup.out`、journald 或容器日志收走，打印口令等于把它复制到一份没人看管的文件里。第一次登录只从 `server/config.yaml` 取一次 `panel.password`，登录后尽快改成自己的（「系统设置 → 账号与口令」，数据不动）。**出厂口令没改之前，平台会拦住建站**：新建钓鱼网站返回 409，并把改口令的入口写在拒绝理由里。

后台默认**只监听 127.0.0.1**：同一网络内其他机器访问不到管理面。确有远程需要时在 `config.yaml` 写 `panel.bind: 0.0.0.0`，启动横幅会就此打印一行 `[提醒]` 告诉你现在整个内网都能到这个后台。

这些值来自 `server/config.yaml` 的 `panel.path` / `panel.port` / `panel.username` / `panel.password` / `panel.bind` / `panel.trust_proxy`。**改口令走界面**：「系统设置 → 账号与口令」（改完所有会话立即失效，需要重新登录，不必重启进程）；也可以直接编辑 `panel.password` 再重启，但那样不会作废已经发出去的会话令牌。

**`panel.trust_proxy` 什么时候才开**：登录失败锁定与「谁在操作」的取证 IP 都取自请求来源。`X-Forwarded-For` 是客户端想写什么就写什么，所以默认**不认**这一行头，只认 TCP 连接的真实对端地址。只有当你确实把管理面挂在 nginx 之类的反向代理后面（此时对端永远等于代理本身，所有访客会被记成同一个 IP）时，才把它置为 `true`。挂反代却不打开，取证 IP 会全记成代理地址；没挂反代却打开，任何人都能用一行请求头绕过登录锁定并伪造取证 IP。

### 1.2 前端（管理界面）

```bash
cd web
npm run dev        # 开发模式（vite，默认 http://localhost:7777）
npm run build      # 产出 web/dist，由后端托管
```

> vite 在本机可能只监听 `[::1]`，所以 `http://localhost:7777/` 能打开、`http://127.0.0.1:7777/` 打不开——遇到"拒绝连接"先换成 `localhost`。
> 用 `npm run build` 后，直接访问后端的管理后台地址即可，不必再起 vite。

### 1.3 登录

打开管理后台地址，会跳到登录页：填「账号」与「口令」，点「进入控制台」。任一项留空会提示「请输入账号与口令」。

- **管理员**：账密通过后直接进入控制台（短信认证对管理员不生效，避免短信欠费或网关异常时把后台锁死）。
- **普通用户 + 短信认证已开启**：账密通过后进入第二步。没绑手机号的先看到「绑定手机号」，填 11 位手机号 →「获取验证码」→ 填 6 位验证码 →「验证并进入」；已绑定的看到「短信验证」，验证码已自动发到掩码号码（如 `138****8000`），按「获取验证码」可重发（受 30 秒间隔限制）。
- 第二步的「返回重新输入账号」可退回账密页；票据 10 分钟内有效，过期后需要重新走第一步。

- 会话有效期由 `session_ttl_hours` 决定（默认 12 小时）。到期后接口返回 401，界面自动清掉本地令牌并送回登录页，重新登录即可。
- 主动退出在顶栏下拉里的「退出登录」，退出后原令牌立即失效；「修改口令」会注销**本账号**的全部会话（其他账号不受影响）。
- **连续输错口令会被按来源 IP 锁定**：10 分钟内失败 8 次，即便口令正确也返回「登录失败次数过多，请 10 分钟后再试」。锁定只影响出错的那个来源，别的 IP 照常登录；成功登录会清零计数。**计数落在 `login_failures` 表里，重启服务不会解除锁定**——爆破痕迹不该因为对方把进程踢重启一次就洗掉。要立刻解锁：停服后 `DELETE FROM login_failures`，或等窗口过去。当前有几个来源被锁，在「系统设置 → 配置体检」的「当前锁定」里能看到。

登录后默认落在「演练总览」。左侧导航按演练动作分组：**演练**（演练总览 / 演练授权）、**素材与投放**（钓鱼素材 / 钓鱼网站 / 钓鱼邮件）、**复盘**（上钩记录）、**系统**（系统设置）。底部「收起导航」可把侧栏收成图标条，状态记在本机浏览器里。

## 2. 三个面：先建立空间感

| 面 | 地址 | 谁在用 | 鉴权 |
|---|---|---|---|
| **管理面** | `http://<主机>:7778/<panel.path>/` 及其下 `/api/*` | 你（操作员） | 必须登录 |
| **钓鱼网站（协议里叫采集面）** | `http://<主机>:<8000-9999 某端口>/` | 演练目标（"中招"的同事） | Host 授权名单 + 演练令牌，无登录 |
| **信标面** | `http://<主机>:7778/alab/health`、`/alab/v2/*` | 邮件客户端、浏览器图片请求 | 公开无鉴权，只认令牌 |

理解这一点能解释很多现象：钓鱼网站用的是**独立端口**，不是后台端口；邮件里的像素和链接现在指向**任务绑定的钓鱼网站端口**（没绑定但只有一个开启中的网站时自动用它），7778 只作为旧邮件与无站点时的回退面；访客侧的匿名 cookie 叫 `alab_tk`，跟管理员的 `alab_token` 会话无关。

## 3. 一次完整演练的标准流程

下面 7 步是推荐顺序，也是「演练总览」里「开工检查」6 个检查项想引导你的路径。

### 第 1 步 · 登记授权（打开授权）

进入「演练授权」，点右上「登记新授权」，弹窗标题是「登记演练授权」。原来要展开抽屉、分四段填表、再逐字抄一遍承诺；现在只要三样东西加一个勾选：

| 字段 | 是否必填 | 怎么填 |
|---|---|---|
| 「授权主体」 | 必填 | 授权文件里的被演练组织，如"某某科技 信息安全部" |
| 「允许仿冒的域名」 | 必填 | 每行一个，默认已带 `#ip`，见下方语法 |
| 「有效期」 | 必填 | 选 7 / 30 / 90 天，或「自定义」后选起止时间；从今天起算，到期自动停站 |
| 合规确认 | 必勾 | 「我确认已获得被测单位的书面授权，并承诺仅在上述时间与域名范围内开展演练」 |
| 「更多信息」 | 选填 | 折叠在底部：对接人、备注（授权文件编号、审批链） |

**Host 授权名单语法**（这个集合同时决定钓鱼网站接受哪些 Host、链接改写允许跳转到哪）：

- `corp.example.com` — 精确匹配，只有这个主机名能通过。
- `*.mail.example.com` — 泛域名，匹配后缀，**含裸域** `mail.example.com`。
- `#ip` — 只允许直接用 IP 访问钓鱼网站。注释里的原话：「#ip 表示只允许直接以 IP 访问，防止把授权范围扩到整段域名」。内网按 IP 直连、没有域名时用这条。

承诺语句仍然原样写进授权记录（服务端硬校验），只是不再要求操作员逐字抄写：勾上合规确认、填完主体与域名，按钮「登记并解锁」才可用；没勾时按钮禁用，旁边写「勾选合规确认后可保存」。

保存后授权立即放行，顶栏徽标从「未授权 · 平台已锁」变为「授权生效」。

**改期与吊销**：
- 授权过期后钓鱼网站会自动停止服务，访客会看到「演练授权已过期，页面已停止服务。」回到「演练授权」点行内「编辑」，把有效期改成 30 天或自定义一个更晚的结束时间即可续期解锁。
- 「吊销」只在该行状态为生效时可用，收在行内「更多」菜单里，会弹「高危操作」确认框：「吊销授权「…将同时停止其下所有钓鱼网站监听，确认？」」。确认后提示「已吊销」，名下所有钓鱼网站**当场下线**——这是演练结束或失控时最该用的刹车。
- 已吊销的授权不可再编辑生效（服务端返回 409）。

### 第 2 步 · 备料（钓鱼素材）

进入「钓鱼素材」，五个标签页：**模板库 / 假登录页 / 邮件文案 / 上钩教学 / 一键仿站**。

- **模板库**（默认页）：随包内置 9 套页面、8 套邮件、4 套教学页，按「页面模板 / 邮件模板 / 教学页」切换，支持按名称、用途或类型搜索。卡片里的缩略图是真实渲染的 4:3 预览，点「预览」可放大看整页，点「使用此模板」复制一份到对应素材列表——复制件叫「xxx（副本）」，可以随意改 HTML 与字段，内置原件不会被改动；想回到原版再复制一份即可。「补齐内置素材」用于旧库升级后一次性写入缺失的内置项。
- **假登录页**：仿冒登录页本体。点「新建假登录页」，在抽屉里配页面名称、需要采集的字段、提交后跳去哪个响应页；可以用「插入骨架」拿一份起手模板，用「智能诊断」/「立即诊断」给页面打分（列表里有「诊断分」，顶部指标有「假登录页 / 可采集字段 / 诊断均分」）。行内「预览」在浏览器里看真实渲染效果，**这一步别省**——诊断分数高不代表肉眼看着像。
  - 诊断有五项：**采集绑定 / 提交触发点 / 外部资源 / 自定义脚本 / 可采集字段**。其中「提交触发点」专盯一件事——页面里到底有没有能触发提交的控件。老模板爱写 `<input type="button" value="立即核验" onclick="login()">`，它不产生 submit 事件，历史上就会出现"目标明明点了，上钩记录一条没有"。现在运行时对这种表单按钮有兜底，采得到，但**别把证据押在兜底上**：这一项没过就扣 25 分，改成 `<button type="submit">` 或加 `data-al-collect` 才稳。
- **邮件文案**：投放用的主题与正文模板。点「新建邮件文案」，支持变量占位（`{{name}}`、`{{email}}` 与 `{{site_url}}` 会在发送时展开）；**正文里写 `{{site_url}}/login` 就行**，发送时会按任务绑定的网站替换成 `域名:端口`，不要手写死管理面地址。绝对链接会被自动改写以便记账，正文里会自动嵌打开像素。
- **上钩教学**：员工"上钩"之后看到的教育页。注意界面提示：「教学页只增不改：保存会生成一条新的教学页记录」——这是上钩记录完整性要求，修改历史版本会破坏记录。
- **一键仿站**：给一个目标地址，让大模型抓取并生成一份假登录页草稿（「使用大模型」「网站名称 / 目标地址」「需要采集的字段」「采样温度」「生成提示词」，点「开始生成」），满意后点「存为假登录页」。这一步只产出草稿，仍需你审。

> 删除保护：删假登录页时，如果它仍被演练网站引用，服务端会拒绝删除（提示「仍被演练网站引用的页面会被服务端拒绝删除」），先下线网站再删素材。

### 第 3 步 · 建钓鱼网站

进入「钓鱼网站」，点「新建钓鱼网站」。抽屉分三区：

1. **绑定素材**：选一张假登录页；「开启状态」选「立即开启」或「先关闭」。
2. **监听地址**：「监听 IP」「监听端口」「监听域名」。端口必须落在 `capture.port_range`（默认 8000-9999）之内，越界会报「监听端口需在 8000-9999 之间」。「监听域名」要与授权名单对得上，否则访客请求会被 404 拒绝。
3. **HTTPS（可选）**：填「TLS 私钥」「TLS 证书」路径。仿冒登录页拿到 HTTPS 更像真的，也更符合"凭据只在演练范围内流动"的要求。

建站后列表能看到「状态 / 假登录页 / 访问地址 / 监听 / 协议 / 授权主体」。行内四个动作：

- 「停止」/「开启」：**没有二次确认**，点了就生效。停止后提示「已停止监听，历史采集记录保留」——证据不会因下线而消失。
- 「链接与上钩」：不跳页，在右侧抽屉里看**这一个网站**的全貌——顶部四个指标（专属链接 / 已打开 / 已提交 / 上钩记录 + 转化率），中间两张表：上面是本站签发过的每一条链接（归属、打开次数、提交次数、采到的字段名、签发时间、行内「复制链接」），下面是本站的上钩记录（目标、首次打开、是否已上钩、停留、来源 IP），**点记录行左边的箭头展开就是逐字段的采集明细**（字段名 / 值 / 采集时间）。抽屉里可以直接「生成专属链接」和「刷新」，签完新链接表格立刻多一行。
- 「生成专属链接」：为这个网站按邮箱生成带令牌的专属投放链接。弹窗「生成专属链接」提示「为该链接登记归属邮箱；留空则签发匿名访客链接，只计打开不认人」，占位 `target@corp.example`。**要给具体人打分就填邮箱；只想测页面效果就留空。**
- 「删除」：确认框「删除会停止该网站监听，已采集的证据保留，确认删除？」。

顶部还有多选批量「删除选中 N」。

### 第 4 步 · 配发信邮箱，建发送任务（钓鱼邮件）

进入「钓鱼邮件」，两个标签页。

**发信邮箱**：点「新增账号」填「配置名称」「SMTP 主机」「端口」「SSL/TLS」「登录账号」「授权码密码」「发信地址」「发件人名称」。

> 口令字段**只写不读**（界面提示「密码只写不读」）：保存后回显是掩码 `******`，再次保存时留空或原样回填掩码都等于"不改这枚口令"。想真的改掉，必须填新值。模型服务的 API Key 同理。

行内「连通性测试」先打一发再上任务，省得到时候分不清是配置错了还是演练被拒。

**发送任务**：点新建，抽屉四区「基础信息 / 素材绑定 / 收件人 / 发送控制」：
- 「素材绑定」选邮件文案模板与**绑定网站**。绑定网站决定三件事：正文里的 `{{site_url}}` 换成哪个 `域名:端口`、正文里的站内绝对链接改写到哪个端口、打开像素落在哪个端口。不绑定时，若全平台只有一个开启中的网站会自动用它；一个都没有时，含 `{{site_url}}` 的任务会在发送前被拦下并提示「正文使用了 `{{site_url}}`，请先给任务绑定一个开启中的钓鱼网站」。
- 「收件人」可以逐个加，也可以「导入收件人」批量粘贴/上传，导入后列表的「收件人 / 已提交」计数会更新（导入完记得看行内「发送」按钮是否已点亮——总数为 0 时它是灰的）；
- 「发送控制」里最关键的是**「沙箱模式」开关**：`沙箱（不真实发信）` / `真实发信`，新建任务默认沙箱。

### 第 5 步 · 沙箱发送与 `.eml` 复核

保持「沙箱模式」打开，点行内「发送」。邮件**不会出网**，而是渲染成 RFC822 文本落到：

```
server/data/outbox/<任务ID前8位>-<收件人邮箱，非法字符换成下划线>.eml
```

文件名带 `X-Sandbox: true` 头。成功提示「沙箱发送完成 N 封，正文已落到 server/data/outbox 供复核」。

**这一步别跳过。** 用邮件客户端打开 `.eml`，检查：主题里的变量有没有正确展开、正文有没有渲染崩、链接改写后的域名与端口是不是**绑定网站**的那个（不是后台的 7778）、像素地址能不能连通、附件是否齐全。沙箱里发现的小错，真实发信时就是一次事故。

单条重发用行内/详情里的「重发」，它会先把该收件人状态退回 `pending` 再投。收件人状态共四种：`pending`（待投）、`sandboxed`（沙箱已落盘）、`sent`（真实已发）、`failed`（失败，可重投）。注意「发送」只处理 `pending` 和 `failed` 的人——已经 `sandboxed` 的人不会重复发送，这不是 bug，想再打一次就单独「重发」。

**切到「真实发信」**：先确认三件事——授权在生效窗口内、已绑定可用的发信邮箱、收件人名单就是授权名单。关掉沙箱开关时界面会亮红条「风险提示：真实发信已开启」。条件不满足会被服务端拒绝：「演练授权无效或已过期，任务拒绝发送。」或「未配置发信邮箱，无法真实发送。」

真发状态下**任何一个发送入口都会先弹「真实发送确认」**：台账行的「发送」、详情抽屉的「开始发送」与「重发待投 / 失败」、编辑抽屉的「保存并发送」、行内的单人「重发」，四条路一条都绕不过去（沙箱模式不进弹窗，仍然一键直投）。弹窗里摊开给你看的是：任务名称、本次将投递几人、名册共几人、SMTP 发件地址、链接会指向哪些域名、当前授权范围与有效期。放行条件是三样都齐——**手输本次待投人数**（输错不给点，也不会告诉你要输几）、**5 秒防手滑等待走完**、服务端这一轮确认没被刷新掉。中途别人把任务拉回沙箱或授权掉了，点「刷新状态」会重读并把原因写在框里；点「取消」不会发出任何东西，审计里也不留投递记录。邮件一旦寄出收不回来，这一屏就是留给你的最后三秒。

### 第 6 步 · 查证据（上钩记录）

进入「上钩记录」，四个标签页。

**网页与邮件分组**（第一屏）：上钩记录先按投放载体分类，两张表——「按钓鱼网页分组」一行一个钓鱼网站，「按钓鱼邮件分组」一行一个发送任务。每行给出监听地址或邮件主题、发送方式（沙箱 / 真实发送）、上钩终端数、页面或邮件打开次数、已提交数、提交率、采到的字段名与最近活动时间。**点任意一行**（或行末「查看上钩记录」）进入这一组的下钻页；顶部四张卡是这一组的汇总，左边是这一组命中的终端列表，右边是选中那条记录的完整详情。

两个口径要记住：

- **网页组**只统计这个网站上的网页采集（`kind=web` 且归属该站点），所以进去后没有「类型」筛选，只有「提交」与搜索。
- **邮件组**把同一个任务发出去的**整条链**算在一起：邮件被打开（像素）、链接被点开、页面上提交了内容，都归到这组，因此进去后「类型」筛选还在，可以用它只看邮件侧或只看网页侧。
- 看板上的数字与点进去左上的「共 N 条」永远相等——两处用的是同一套过滤条件，不会出现"板上写 3 条、进去只有 2 条"。
- **没钓到人的载体也照样挂在板上**（上钩终端 0），一行都不能少，否则"这个页面没人上当"这个结论本身就没处可查。已经删掉的网站与任务也一样出现，标签写「已收网」「任务已删」——收网删的是监听配置，不是已经采到的证据。
- 万一历史数据里有既没挂在网站也没挂在任务下的记录，会单列成「未归属记录」一格（为 0 时这一格不显示），点进去照样能逐条看。

想不按载体、直接翻全库记录，点看板右上角的「全部上钩记录」。

下钻页里：已提交的人带「已提交」标记；右侧「上钩记录详情」面板看**设备与行为特征**、**提交历史**（同一终端多次提交都会保留）、**采集字段**（字段 / 采集值 / 记录时间）与**客户端截图**。看完点左上「返回分组」回到看板，看板会重新取一次数。

> **凭据字段默认是掩码的**：账号、口令这类字段在列表与详情里一律显示成掩码，要看原值得逐个字段点开，而每一次点开都会留下一条审计（谁、什么时候、看了哪条记录的哪个字段）。想成批拿到原值只能走「导出报表」的取证 CSV——那一份是明文，因为事后要核实访客到底填了什么，导出动作会同时留 `push_logs` 与 `evidence.export` 两道痕。给甲方的交付物（演练报告、按授权导出的 CSV）则是掩码版，别把两份搞混。
>
> 删除确认是「确认删除这条上钩记录？删除后不可恢复。」——报告要用的证据先导出再删。

**导出报表**：选「网页采集」或「邮件采集」，点「导出网页证据（awarelab-web-evidence.csv）」或对应邮件按钮，下载 `awarelab-web-evidence.csv` / `awarelab-mail-evidence.csv`。CSV 列固定，可直接喂给报表。导出动作本身也会在下一次刷新里作为一条通知记录（通道为 `export`）。

**通知记录**：列表列「时间 / 通道 / 事件 / 结果（成功/失败）/ 响应」，行内「请求体」看原始 payload。所有外发通知统一带前缀 `[AwareLab 演练通知]`。推送失败不影响采集主链路，所以这一页出现红色"失败"时，证据仍在，只是没送到群/邮箱。

**操作审计**：这一页记的是**操作员在平台上做的高危动作**，与上面的通知记录分职——通知记录说"平台往外发了什么"，操作审计说"谁动了平台"。列「时间 / 操作人 / 动作 / 来源 / 对象 / 详情」，可按动作下拉筛选、按操作人搜索，点「查看」看当时的取值。覆盖六类：

| 动作 | 什么时候写 | 详情里能看到 |
|---|---|---|
| 登记授权 / 修改授权 / 吊销授权 | 授权增删改 | 授权主体、改动前后的有效期与域名名单、连带停掉了几个站点 |
| 关闭发信沙箱 | 任务从"只渲染"翻成"真发信"（或翻回来） | `from` / `to` 各自是 sandbox 还是 real |
| 沙箱发信 / 真实发送 | 点「发送」 | 任务、收件人条数 |
| 导出证据 | 下载 CSV | 导走的是网页侧还是邮件侧、多少行 |
| 删除上钩记录 / 删除钓鱼站点 / 删除发信任务 | 对应删除动作 | 被删对象 ID；删站点时还记它挂了哪个端口、名下留了几条证据 |
| 修改运行参数 | 保存模型服务或推送配置 | 改了哪个键、厂商/通道的形状；**密钥与机器人令牌已掩码，审计表不是第二份密码本** |

这张表只读：没有改和删的接口。理由很直白——审计一旦能事后修饰，就不再是审计。写入失败只在控制台告警、不阻断采集与发信，所以某条动作若缺失，先看服务日志而不是怀疑界面。

### 第 7 步 · 收尾

演练窗口一结束，回到「演练授权」点该行的「吊销」。**这会同时停掉名下所有钓鱼网站监听**，是最干净的一次性刹车——比逐个网站手点「停止」可靠，也不会有人忘。

吊销后访客再访问钓鱼网站地址会得到 403「当前无有效演练授权…」。到这一步，把「导出报表」的 CSV、`server/data/outbox/` 的 `.eml`、报告文档一起归档，并按授权文件约定销毁原始凭据。

左侧导航底部「观测视图」进入 `/screen`，脱离管理端外壳独占整屏，页内可点「全屏」和「返回控制台」。大屏分三种，互相独立、都可直接投屏：

- **总览大屏** `/screen`：所有站点与任务叠在一起看——顶栏 6 个 KPI（运行中网站 / 已打开终端 / 已提交内容 / 邮件收件人 / 整体转化率 / 未受骗率），左栏中招漏斗、邮件链路、终端分布，中间七日趋势 + 网站墙，右栏任务墙 + 浏览器分布 + 最新命中流水。

进大屏的入口有三处：顶栏下拉/左侧导航的「观测视图」、钓鱼网站列表行内「大屏」、钓鱼邮件列表行内「大屏」。任一屏都能用右上角的选择器直接切到别的站点或任务，不用退回列表。

注意两种口径不要相加：网页侧「已打开」指打开过假登录页的终端，「已提交」指真的交回内容；邮件侧按登记收件人算打开/点击/提交。页脚「口径」一行写的就是这件事。

## 6. 系统设置

「系统设置」两个标签页：**运行参数 / 协议文档**。

**运行参数**（部分项只读，因为它们是硬性边界）：
- 「演练边界」区的「授权硬性要求」：chip 只读显示「授权硬性要求：开启」，说明「require_authorization 属硬性要求，不提供在线关闭入口」。要在界面上关掉它是不可能的——这是设计，不是漏做。
- 「平台运行参数」里的「邮件默认沙箱」：**只读展示**「是（不真实发信）」或「否（真实发送）」，改它要在 `server/config.yaml` 调 `mail.default_dry_run`。任务级的「沙箱模式」开关才是给你按任务控制的。
- 同样只读的还有 `panel_path`、`panel_port`、`db_driver`、`db_path`、`capture_port_range`。
- 可编辑：「模型服务」——配 AI 厂商（「新增厂商」→ 填名称/Base URL/模型/API Key → 点「确定」→ 点「保存模型服务」才落库，中间那一步容易漏），API Key 掩码回显；「通知通道」——「启用事件推送」开关 + 「脱敏推送」开关 + 新增通道 + 「保存推送配置」。
- 「脱敏推送」默认开启：推到群里的消息里**不出现员工邮箱与采集字段名**，收件人换成 `员工#<8位摘要>`（同一邮箱每次得到同一个代号，你照样能对上号），字段只报"几项"。想按原样推给自己看，把开关关掉即可，这个选择本身也会进操作审计。
- 推送与模型服务的地址都受协议约束：公网只收 `https`，明文 `http` 只放行 `127.0.0.1` / `localhost` / `::1`（本地联调用）。填 `http://机器人域名/...` 会被 400 拒掉，因为那等于把员工上钩事件连同机器人令牌裸寄出去。
- 机器人令牌写在 URL 的 query 里（`?access_token=…&sign=…`），推送日志落库前会把这类参数换成 `******`；日志里看到星号是正常形态，不是配置丢了。

### 6.1 账号管理（管理员）

左侧「系统 → 账号管理」只有管理员能看到。页面顶部三格是账号总数、启用中的管理员数、短信认证状态；下面一张表列出全部账号。

- **管理员账号只能由启动配置产生**：`config.yaml` 的 `panel.username` / `panel.password` 在首次启动时种进 `users` 表，界面不提供「新建管理员」和「把普通用户提成管理员」——提权必须落成一次文件改动，不能点两下就完成。
- **新建普通用户**：「新建普通用户」→ 账号（3–32 位字母数字与 `_.-`）、显示名、初始口令（8–64 位）、手机号（可选，先填的话登录时不必再绑）→ 确定。普通用户默认启用。
- **重置口令**：行内「重置口令」填新口令即可，不需要知道旧口令；该账号的现有会话会全部失效。
- **停用 / 启用**：停用后该账号立刻登录不上（已登录的会话在下一次请求时被判 401）。系统不允许停用或删除最后一个启用中的管理员，也不允许停用当前登录的自己。
- **删除**：连带删掉该账号的会话；不能删自己。
- 手机号列显示掩码（`138****8000`）与「已验证 / 待验证」状态；管理员行的操作只保留「编辑」（改显示名与手机号），避免把唯一的管理员锁在门外。

### 6.2 短信认证（阿里云号码认证）

「系统设置 → 短信认证」用来接阿里云号码认证服务（Dypnsapi）的发码与验码接口。**默认关闭**；管理员填好密钥后打开开关才生效，对管理员账号始终不生效。

| 字段 | 说明 |
|---|---|
| AccessKey ID / Secret | RAM 用户的 AK；Secret 只以掩码回显，留空或原样回填掩码＝不改。建议只授 `dypns:SendSmsVerifyCode` 与 `dypns:CheckSmsVerifyCode` 两项权限 |
| 短信签名 | 在阿里云短信控制台审核通过的签名，例如「远山科技」 |
| 模板 CODE | 验证码模板的 CODE（数字）；模板正文里用 `${code}` 占位，验证码由阿里云生成后填入 |
| 模板参数 | 只放模板里的**其它**变量，例如 `{"name":"张三"}`；没有就留空。**不要写 `code`**——验证码不是客户端传的，写了会回 `isv.INVALID_PARAMETERS`「请检查模板内容与模板参数是否匹配」 |
| 验证码位数 | 4–8，默认 6 |
| 有效期（秒） | 60–1800，默认 300；超过后验证码作废 |
| 重发间隔（秒） | 30–600，默认 30；同一号码在这个窗口内重发会被 429 拒掉 |
| 高级：网关地址 / 方案名 | 默认 `dypnsapi.aliyuncs.com`；只允许 `https`，本机回环可写 `http` 便于联调。方案名对应控制台的号码认证方案，留空则用默认 |

- 保存时如果开关是开的但密钥不全，接口仍返回成功，同时带一条 warning 提示缺哪几项，页面上也会显示「配置未就绪」；这种状态下普通用户登录不会被拦（按未开启处理），避免把自己锁在外面。
- 开启后普通用户第一次登录会先要求绑定手机号，绑定成功后当场进入控制台；之后再登录就是「账密 + 验证码」。管理员不受影响。
- 每次发码都写 `sms_send_log`（号码、用途、来源 IP、网关请求号、成败），「上钩记录 → 通知记录」之外的这类运维留痕用它排查；限流按同号 60 秒、同号 5 次/小时、同 IP 20 次/小时三档执行。
- 想临时停用：把开关关掉并保存即可，无需重启；已经发出的验证码在有效期内仍可校验。

**协议文档**：一份只读的协议文档（9 小节），是访客端与信标端的权威接口契约。排查采集不上、链接没记账时先对照这一页，而不是猜。

## 7. 排障速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 访客访问钓鱼网站地址得 403「当前无有效演练授权…」 | 没登记授权，或授权已吊销 | 去「演练授权」登记/续期 |
| 访客访问钓鱼网站得 410「演练授权已过期，页面已停止服务。」 | 授权结束时间已过 | 编辑授权、把有效期改成 30 天或自定义一个更晚的结束时间，保存即生效 |
| 收到的邮件里链接域名是后台的 7778，不是 8080 | 任务没绑定网站，且平台里没有任何开启中的站点，合成器退回管理面地址 | 先「钓鱼网站」确认目标站点处于监听中，再到任务「素材绑定 → 绑定网站」选它；改完重新发一轮，`.eml` 里应出现 `:8080/alab/v2/trace` |
| 大屏切到某个站点/任务提示「观测对象不存在」 | 该站点或任务已被删除，浏览器还停在旧链接 | 点右上角选择器回到总览，或从列表重新点「大屏」；深链刷新也会得到同样的 404 |
| 大屏上「已打开」与「邮件已打开」对不上 | 两套口径：网页侧按终端算打开，邮件侧按登记收件人算 | 页脚「口径」已写明不可相加；看某个人走到哪一步用「上钩记录」的邮件组 |
| 内置模板库里点「使用此模板」后列表没看到副本 | 副本落在对应的素材页签，模板库页签按设计只放原件 | 切到「假登录页 / 邮件文案 / 教学页」页签，列表顶部就是新副本 |
| 钓鱼网站访问域名得 404「访问用的域名 … 不在授权名单内，已拒绝服务。」 | 访问域名不在 `allowed_hosts` 里 | 用授权名单内的域名/IP 访问，或补一行 `*.domain` / `#ip` |
| 建站/发送被拒 403 | 同上，授权不只看访客也看操作员动作 | 先开授权 |
| 打开专属链接、填了内容点了提交，「上钩记录」里却只有打开没有提交 | 页面里没有能触发提交的控件——手写/仿站模板爱把提交做成 `<input type="button" onclick="login()">`，它不触发 submit 事件，也没声明采集点 | 看「钓鱼素材 → 立即诊断」的**提交触发点**一项；改成 `<button type="submit">` 或加 `data-al-collect`。运行时已对这种表单按钮兜底，但兜底要**重启后端**才生效（采集运行时的代码在服务进程里，不是站点重启能换的） |
| 登录 429「登录失败次数过多，请 10 分钟后再试」 | 同来源 10 分钟内失败 8 次 | 等 10 分钟，或换来源；重启服务也会清零 |
| 普通用户登录后停在第二步，收不到验证码 | 短信认证开着但 AK/签名/模板不全，或阿里云欠费、号码不在白名单 | 看「系统设置 → 短信认证」是否显示「配置未就绪」，再查 `sms_send_log` 的 `ok` 与 `message`；临时处理可先关掉开关 |
| 发码 429「发送过于频繁，请 N 秒后再试」 | 同一号码 30 秒内重复点「获取验证码」 | 等倒计时结束；或把「重发间隔」调小（最低 30 秒） |
| 验证码一直提示错误或已过期 | 码已过有效期、用了上一条码，或网关返回不是 PASS | 在有效期内用最新一条；仍失败看 `sms_send_log` 与后端日志里的 `[sms]` |
| 管理员开短信后自己也要求验证码 | 不会发生：短信认证只对普通用户生效 | 如果你确实被拦，说明当前账号在 `users` 里不是 `admin`，用启动配置的管理员账号登录后修正角色 |
| 投了但 `outbox` 里没 `.eml` | 该收件人状态已是 `sandboxed`/`sent`，「发送」只挑 `pending`/`failed` | 用「重发」 |
| 行内「发送」按钮是灰的 | 任务收件人总数为 0 | 导入或添加收件人后刷新 |
| 保存后 SMTP 口令 / API Key 变成 `******` | 正常：读取一律掩码 | 留空或原样回填掩码＝不改；要改就填新值 |
| 改 AI 厂商名字后 Key 失效 | 老数据无行身份 id 时按名称兜底可能对不上 | 保存一次让服务端补齐 id；确认发信时不要用掩码当 Key |
| 改了 `config.yaml` 不生效 | 配置只在启动时读 | 重启后端 |
| 载荷回传 400「回传令牌不属于本次演练」 | 令牌不是这次演练发出的（手写/复用旧令牌） | 用任务里该收件人的 `tk`；确认载荷把令牌原样带回来 |
| 载荷回传 410「本次演练授权已不在有效期内」 | 授权已吊销或过期，回传通道按设计关闭 | 续期或重新登记授权后再跑载荷 |
| 载荷回传 429 | 同一令牌每分钟超 10 次，或同一来源 IP 超 200 次 | 载荷改成"一次运行回报一次"；确有需要时调 `capture.callback` 阈值 |
| 回调成功但记录里没有截图 | 文件头不是 png/jpeg/pdf/zip、扩展名与内容不符，或 `data/screenshots` 已达 512MB 配额 | 看「上钩记录 → 通知记录」旁边的事件与 `server.log` 里的 `[beacon] 截图落盘…` 告警；清理截图目录后恢复 |
| 回调的某个字段没进证据 | 字段名不合规、超过 40 个字段，或令牌绑了站点而模板没声明这个 `name` | 改成模板里的输入名，或把字段数降下来；被丢弃的字段名会作为 `callback_fields_dropped` 事件留痕，`GET /api/records/<记录ID>` 的 `events` 里能看到 |
| 操作审计里少了一条动作 | 审计写入失败只告警不阻断链路 | 查 `server.log` 的 `[audit] 审计写入失败`；缺的那条要在报告里注明 |
| 「操作审计」整页空白、接口报错 | 旧库还没升到带审计表的版本：`audit_logs` 随新代码启动时按 `PRAGMA user_version` 逐级建表，不改任何既有数据 | 重启一次后端；重启前想用真实数据验一遍，见 README「验证」里的 `E2E_SEED` 用法 |
| `http://127.0.0.1:7777` 打不开 | vite 只监听 `[::1]` | 用 `http://localhost:7777/` |
| 看板上某个钓鱼网页是 0 条，但确定有人提交过 | 这条证据归属在**别的组**：一个 `tk` 的记录按"类型 + 令牌"唯一，A 站的专属链接被人拿到 B 站页面上提交，证据仍记在 A 站那组 | 用看板右上角「全部上钩记录」按邮箱或令牌搜索，看详情里的「网站模板 / 发送任务」落到哪；投放时一发一链、一站一链，别混用 |
| 网页组与邮件组的数字对不上 | 两个口径本来就不同：网页组只算本站的网页采集，邮件组把**邮件打开 + 链接点开 + 后续网页提交**算在同一条链上 | 两侧数字不要相加；要看某人到底走到哪一步，进邮件组后按「类型」筛出网页侧记录 |
| 通知记录里有失败 | 推送通道问题 | 不影响采集，证据仍在「上钩记录」；修通道后看下一次事件 |
| 界面上的时间和事件实际发生的时间对不上（老版本差 8 小时） | 平台一律按 UTC 存时间，早期版本又按 UTC 显示，不同界面口径还不一致 | 现在所有时间一律换成本机时区显示（存法不变，只是给人看的一律本地化）。同一时刻在两个界面不一致属回归，按缺陷报 |
| 访客打开仿冒页只看到「页面不存在或已下线」「该页面暂时无法访问」，看不出是演练 | 设计如此：演练对象能看到的每一屏都不许出现「演练 / 授权 / 采集」这些内部词，否则当场泄密、这次演练作废 | 拒绝原因看管理面与「上钩记录 → 操作审计」；访客侧文案要改，只能改成同样中性的说法 |
| 任务列表显示「全部失败」但记得点过「发送」 | 一封都没发出去（SMTP 不可达、收件人全被拒等）。老版本这里会谎报「已发送」 | 展开收件人看逐人失败原因，修通道后用「重发」；部分成功标「部分失败」 |

## 8. 数据位置与安全须知

- SQLite 库：`server/data/awarelab.db`（路径由环境变量 `AWARELAB_DATA` 或默认 `<server>/data` 决定）。
- 沙箱邮件产物：`server/data/outbox/*.eml`。
- 配置：`server/config.yaml`（可用 `AWARELAB_CONFIG` 覆盖位置）。
- 回传截图：`server/data/screenshots/`（只落 png/jpeg/pdf/zip，累计 512MB 后拒绝继续写入并在控制台告警，清理这里就能恢复）。
- 操作审计：同库的 `audit_logs` 表，只增不改不删，随 `awarelab.db` 一起备份——归档演练材料时别只导 CSV，审计表才是"谁在什么时候动的平台"的那份自证。

**以下路径已在 `.gitignore` 里，绝不要提交或推送到任何仓库**：

```
server/config.yaml    # 含后台路径、账号密码，只留本机
server/data/          # 采集到的凭据、邮件产物、附件、截图
```

备份/迁移时把 `server/config.yaml` 和 `server/data/` 一起搬——离开那 32 位随机路径和库文件，界面和证据都找不回来。搬完记得用 `npm test`（它只在 `server/.selftest/` 隔离副本上跑，不碰真实数据）验证一把。

清理演练数据的正确姿势：先「吊销」授权停掉所有采集，再决定归档还是删除；逐条删记录不可恢复，删库前先导出 CSV。

## 9. 验证工具（操作员自用）

```bash
cd server && npm test          # 端到端断言（隔离数据副本 + 独立端口）
cd server && node scripts/smoke.mjs  # 对着已在跑的服务做只读体检：不建站、不发信、不写库
cd server && node scripts/verify-mail-links.mjs  # 邮件链路回归：只验证链接落在网站端口，不碰真实数据
cd server && node scripts/verify-sms.mjs        # 账号与短信回归：本地假网关，不访问真实阿里云
cd web && npm run build        # 前端构建校验
```

`smoke.mjs` 自己从 `server/config.yaml` 读后台路径与账号口令，所以它会用你的真实凭据登录一次（成功登录会清零失败计数，不会把你锁在门外）。改完配置重启后先跑一发，确认三面活着、授权状态正常，再开始真实演练。

`verify-mail-links.mjs` 会在隔离目录里起一套实例（管理面 4311、网站 8201），建站、绑定任务、沙箱发信后解析 `.eml`，断言链接与像素落在 `:8201`、`trace` 302、无站时 `{{site_url}}` 被拦。改过邮件合成或采集面路由后先跑它，比肉眼看 `.eml` 快。
