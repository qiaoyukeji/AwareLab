# 演练值守与缺陷分级

> 这份文档只服务一个场景：**演练正在进行，出了事，值班人在 5 分钟内知道该做什么。**
> 部署与备份见 [部署与运维手册](部署与运维手册.md)；日常操作见 [使用手册](使用手册.md)。
> 上线前请把它打印一份放在值守位，或至少让值班人读完 §2 与 §3。

---

## 1. 值守角色与交底

| 角色 | 谁 | 职责 | 交接物 |
| --- | --- | --- | --- |
| 演练负责人 | 业主或其指定安全负责人 | 决定"继续 / 暂停 / 终止"，对外沟通 | 授权文书、允许仿冒域名清单、终止口令 |
| 平台操作员 | 跑这台机器的人 | 建站、发信、看证据、执行止血动作 | 后台入口、`config.yaml` 位置 |
| 值班人 | 演练时段内盯屏幕的人 | 按本文档判级、止血、登记、上报 | 本文档 §2/§3、缺陷台账 |
| 开发支持 | 能改代码的人 | S1/S2 的根因定位与修复 | 仓库、`ci.mjs` |

**交底三问**（上岗前值班人要能答出来，答不出来就别上岗）：

1. 现在生效的授权覆盖哪些域名、到什么时候？
2. 采集断流了，第一个看的地址是什么？（答：`http://127.0.0.1:7778/alab/health`）
3. 需要立刻把所有钓鱼页面撤下来，最快的一招是什么？（答：停服务进程；见 §3 S2 止血①）

## 2. 缺陷分级与响应时限

分级的唯一标准是**它是否让演练失去可信度或失去控制**，不是"看起来严不严重"。

| 级别 | 定义 | 典型现象 | 响应 | 止血时限 | 上报 |
| --- | --- | --- | --- | --- | --- |
| **S1 采集断流** | 演练对象做了动作，平台没记下证据 | 上钩记录不增长；`/alab/health` 不通；站点显示已停；回传 429/410 | 立即 | **10 分钟**内止血或宣布暂停 | 立即通知演练负责人 |
| **S2 门禁失效** | 平台做了授权范围外的事，或该拦的没拦 | 无授权也能建站/发信；名单外域名被仿冒；真发信在沙箱应为开启时发生；后台被陌生来源访问 | 立即 | **5 分钟**内撤下所有投放 | 立即通知演练负责人 + 开发支持，当天出书面说明 |
| **S3 界面与文案** | 不影响数据与合规，只影响可读性 | 文案错别字、数字口径看着别扭、按钮位置反人类、图表标签被截断 | 当天登记 | 演练结束后修 | 记入台账，不打断演练 |

判级口诀：**证据没了是 S1，边界破了是 S2，难看是 S3。**
拿不准就按高一级处理——多停一次演练的代价，远小于让一次越界投放继续跑。

不要新开 S4："轻微问题"会在值守压力下变成"不登记"，S3 就是最低档，难看也登记。

## 3. 分级处置手册

### S1 · 采集断流

**目标：10 分钟内恢复采集，或明确宣布"这段时间的数据不可信"。**

按顺序排，每一步都先看再动：

1. **进程还活着吗**
   ```bash
   curl -i http://127.0.0.1:7778/alab/health      # 期望 200 + ok
   ```
   这条健康检查是公开无鉴权的，也是冒烟脚本的第 0 步（[server/src/boot/main.js:101-102](../server/src/boot/main.js#L101-L102)）。
   不通 → 看日志（`journalctl -u awarelab -n 80`）。若是 `EADDRINUSE`，说明 7778 被占，进程根本没起来：
   这一类**刻意不兜**，兜住会让操作员以为服务已经起来了（[main.js:73-74](../server/src/boot/main.js#L73-L74)）。释放端口或改 `panel.port`，重启。**不要反复重启碰运气**，先看错误行；
   如果日志是一段中文"配置校验未通过"，那是配错了配置项，按提示改（[server/src/platform/configCheck.js:54-92](../server/src/platform/configCheck.js#L54-L92)）。

2. **站点还在听吗**
   界面「网站监听」看每个站点的运行状态；`running` 是从进程内的监听注册表实时读的，库里的 `status` 只是**运维意图**，
   两者可以不一致（[server/src/capture/siteRegistry.js:10-12](../server/src/capture/siteRegistry.js#L10-L12)，证据页判"在不在听"用的就是 `isRunning()`）。
   显示已停 → 点开启（`POST /web-sites/:id/start`，[server/src/api/siteApi.js:141-147](../server/src/api/siteApi.js#L141-L147)）；开不起来看第 3、4 步。
   注意端口起不来是**异步**失败的：界面上先显示"开启中"，随后 `listen` 的 error 回调把行写成 `status=error`（[siteRegistry.js:83-88](../server/src/capture/siteRegistry.js#L83-L88)）。
   还有一个好用的分流：访客在页面上的行为上报 `/alab/v2/engage` **不走 7778**，由该站点自己的采集监听收
   （[beaconPlane.js:283-284](../server/src/channels/beaconPlane.js#L283-L284)）。所以"`/alab/health` 通、`engage` 不通"= 那个站点的端口没在听，不是主进程挂了；
   反过来"邮件里的像素/链接完全没反应"才先怀疑主端口或令牌。

3. **授权还在窗口内吗**
   授权过期或被吊销后，采集回传会返回 **410**（[server/src/channels/beaconPlane.js:284-287](../server/src/channels/beaconPlane.js#L284-L287)），
   站点也会被平台强制下线：`closeSitesOfAuthorization()` 把行写成 `status='closed'`、`close_reason='authorization'`
   （[siteRegistry.js:124-133](../server/src/capture/siteRegistry.js#L124-L133)）。这是门禁在正常工作，不是故障。
   处置：去「演练授权」续期或重新登记。续期后 `reopenSitesOfAuthorization()` **只**把 `close_reason='authorization'` 的那批自动放回去
   （[siteRegistry.js:94-100](../server/src/capture/siteRegistry.js#L94-L100)）；操作员主动收网的（`manual`）**永远不会**被自动掀开，要手工点开启——
   取值口径见 [server/src/platform/storage/schema.js:45-46](../server/src/platform/storage/schema.js#L45-L46)，细节见运维手册 §6。

4. **是不是被限流挡了**
   回传面是公开无鉴权入口，带限流：单令牌 10 次/分、单来源 200 次/分，超限 **429**
   （阈值默认值 [server/src/platform/settings.js:101-102](../server/src/platform/settings.js#L101-L102)，执行点与中文提示 [server/src/channels/beaconPlane.js:46-53](../server/src/channels/beaconPlane.js#L46-L53)、[beaconPlane.js:366](../server/src/channels/beaconPlane.js#L366)）。
   演练对象集中在同一出口 NAT 后面时容易撞到 `per_ip_per_minute`。
   处置：临时上调 `capture.callback.per_ip_per_minute` 并重启（记入台账，演练后调回）。
   **不要**为此关掉限流或打开 `trust_proxy`——后者会让任何人都能伪造来源身份（[settings.js:79-82](../server/src/platform/settings.js#L79-L82)）。

5. **素材里到底有没有采集点**
   钓鱼页能打开、访客也填了，但记录是空的：常见原因是素材里只有一个 `<form>`，没有协议 v2 的声明式绑定。
   处置：换用平台自带的假登录页模板验证一次（能采到 = 素材问题，不是平台问题），再改素材；
   改完可以先跑一次模板体检（`POST /web-templates/diagnose`，只提示不阻断，[web/src/workspaces/material/PagePane.vue:10](../web/src/workspaces/material/PagePane.vue#L10)）。

6. **磁盘满了吗**
   `data/screenshots` 有总配额（默认 512MB，[settings.js:103-104](../server/src/platform/settings.js#L103-L104)），超了不再落新截图（配额累计与落盘见 [beaconPlane.js:219-252](../server/src/channels/beaconPlane.js#L219-L252)）；
   库文件所在盘满了会让写入静默失败。
   处置：`node server/scripts/purge.mjs --status` 看过期文件数（[server/scripts/purge.mjs:94-107](../server/scripts/purge.mjs#L94-L107)），必要时 `--sweep`。

7. **确认影响面**
   恢复后立刻记下"断流起止时间"，写进台账与当天的演练日志。
   这段时间的上钩率不可信，报告里必须说明——**宁可少一个百分点，不要一个假数字。**
   被拒的回传其实有留痕：`events` 表里 `kind=callback_rejected` 的行带着拒绝理由短码（[beaconPlane.js:260-264](../server/src/channels/beaconPlane.js#L260-L264)），
   排"是载荷写错了还是有人在打平台"就看它。

### S2 · 门禁失效

**目标：5 分钟内让平台停止一切投放，然后才谈为什么。**

止血动作按这个顺序，**做完第 ① 步就已经不再扩大了**：

1. **撤下所有投放**（三选一，从快到慢）
   - 最快：停服务进程。优雅停机会**先掀掉所有仿冒端口，再关主端口**（[server/src/boot/main.js:99-106](../server/src/boot/main.js#L99-L106)）：
     ```bash
     sudo systemctl stop awarelab        # Windows: nssm stop AwareLab
     ```
     别用 `kill -9`：端口没走完 `close()`，下次启动会撞一片 `status=error`（[siteRegistry.js:124-128](../server/src/capture/siteRegistry.js#L124-L128)）。
   - 只撤页面、保留后台：界面「网站监听」逐个点收网（`POST /web-sites/:id/stop`，[siteApi.js:164-176](../server/src/api/siteApi.js#L164-L176)）。
     收网**刻意不过授权门禁**——演练失控时第一件事必须是能立刻把页面撤下来（同文件 170 行的注释就是这条裁决的理由）。
   - 撤投递：`DELETE /mail-tasks/:id` 删掉还没发出去的任务与名册（删除属收网侧动作，不设门禁，[campaignApi.js:234-243](../server/src/api/campaignApi.js#L234-L243)）。
     **但一轮 `/send` 一旦开跑就没有暂停或中止接口**：授权只在入口判一次（[campaignRunner.js:13-17](../server/src/mail/campaignRunner.js#L13-L17)），
     循环里逐封不再复查（同文件 136 行起）。所以真发信跑起来时，能做的只有"不发下一轮"+ 立刻从 SMTP 出口侧停发（改账号或让邮箱服务商拦截）。

2. **确认边界已经收回**
   ```bash
   ss -ltnp | grep -E '80[0-9][0-9]'     # 应该一个采集端口都不剩
   ```
   平台侧核对：界面「网站监听」的 `running` 全部为假——**别看库里的 `status`**，那个是运维意图（[siteRegistry.js:10-12](../server/src/capture/siteRegistry.js#L10-L12)）。

3. **查清"已经发生了什么"**（这一步不许跳过，也不许在止血之前做）
   - 「证据 → 操作审计」按时间倒序看（`GET /audit-logs`，可按 `action` 精确筛，[server/src/api/evidenceApi.js:466-472](../server/src/api/evidenceApi.js#L466-L472)）：
     `site.create`（[siteApi.js:115](../server/src/api/siteApi.js#L115)）、`mail_task.real_send`（[campaignApi.js:207](../server/src/api/campaignApi.js#L207)）、
     `authorization.create/update/revoke`（[mandateApi.js:101](../server/src/api/mandateApi.js#L101)、[93](../server/src/api/mandateApi.js#L93)、[119](../server/src/api/mandateApi.js#L119)）、
     `settings.update`（[platformApi.js:205-223](../server/src/api/platformApi.js#L205-L223)）；
   - 「外发流水」看推送与导出去向（`push_logs`，导出动作也会在这里留一行，[evidenceApi.js:453-456](../server/src/api/evidenceApi.js#L453-L456)）；
   - 沙箱应为开启却真发信了：查 `mail_tasks.dry_run` 与 `mail.default_dry_run`（[settings.js:111](../server/src/platform/settings.js#L111)），
     以及 `mail_task.sandbox_toggle` 审计——**谁在什么时候关的沙箱，审计里有**（[campaignApi.js:162-187](../server/src/api/campaignApi.js#L162-L187)）。

4. **恢复门禁**
   - `exercise.require_authorization` 被改成 `false` → 改回 `true` 并重启（默认值与理由见 [settings.js:116-120](../server/src/platform/settings.js#L116-L120)；**没有在线关闭的口子**，改配置是唯一途径）；
   - 授权范围不够导致越界 → 不是"放宽门禁"，而是**重新登记一份范围正确的授权**（`allowed_hosts` 逐行核对）；
   - 后台被陌生来源访问 → 设 `panel.allow_ips`、改口令、`POST /auth/sessions/revoke-all` 注销所有会话（含自己，[sessionApi.js:35-36](../server/src/api/sessionApi.js#L35-L36)），
     并查 `login_failures` 是否出现非本机 IP 的失败累计（爆破锁定是落库的，重启不解除，[session.js:7-13](../server/src/security/session.js#L7-L13)；
     `GET /config-check` 的 `login_security.active_locks` 能直接给出此刻被锁来源数，[session.js:270-291](../server/src/security/session.js#L270-L291)）。

5. **上报与书面说明**
   立即通知演练负责人与开发支持；当天出一份说明：发生了什么、影响哪些人/域名、
   何时发现、何时止血、根因、后续措施。附件用审计导出，不要手抄。

6. **是否继续演练**
   由演练负责人决定。默认答案是**暂停到根因清楚为止**——门禁失效意味着这段时间的所有数据都不能作为结论依据。

### S3 · 界面与文案

**目标：不打断演练，但一条都不漏。**

1. 当场登记进 [整改台账模板](templates/整改台账模板.csv)：至少填**编号、级别、发现渠道、现象（可见事实）、验证人 + 日期**这一侧的信息，
   现象一栏要把"在哪个页面、点了什么、看到什么"写清楚（列名与示例行见模板第 1-2 行，本文档 §7 有对照说明）；
2. 截图时**先确认画面里没有明文口令、完整邮箱、后台随机路径**——有就打码或只截局部；
   凭据字段在列表与详情里默认是掩码的，明文只能走 `POST /records/:id/reveal` 且会写 `record.secret_reveal` 审计
   （[server/src/api/evidenceApi.js:11](../server/src/api/evidenceApi.js#L11)、[evidenceApi.js:391-407](../server/src/api/evidenceApi.js#L391-L407)），所以截图里出现明文 = 有人点过"查看明文"，审计能查到；
3. 继续演练，不要现场改代码。值守期间改前端等于给自己造一个 S1：**改完必须 `vite build` 并重启后端才生效**
   （SPA 外壳只在挂载时读一次，[server/src/channels/adminPlane.js:34](../server/src/channels/adminPlane.js#L34)），而重启会短暂断采集；
4. 演练结束后统一修，修完跑 `node server/scripts/ci.mjs` 再发版（[server/scripts/ci.mjs:1-20](../server/scripts/ci.mjs#L1-L20)）。

## 4. 值守期的观测点

演练进行时，这几处每 15 分钟扫一眼：

| 看什么 | 在哪 | 正常长什么样 |
| --- | --- | --- |
| 进程活着 | `GET /alab/health`（公开无鉴权，[beaconPlane.js:292](../server/src/channels/beaconPlane.js#L292)） | 200 + `ok` |
| 上钩在增长 | 「证据 → 上钩看板」（`GET /records/groups`，[evidenceApi.js:216](../server/src/api/evidenceApi.js#L216)） | 分组数字随投放推进上涨；每组的 `unhandled`（该组里还没做安全教育的终端数，[evidenceApi.js:213](../server/src/api/evidenceApi.js#L213)）随教育推进下降 |
| 实时流水 | 大屏 / `GET /stats/bigscreen`（[insightApi.js:142](../server/src/api/insightApi.js#L142)） | 最新事件时间贴近当前时间（差 10 分钟以上说明断流了） |
| 站点在听 | 「网站监听」 | `running` 为真——**只看 `running`，别拿库里的 `status` 猜**（[siteRegistry.js:10-12](../server/src/capture/siteRegistry.js#L10-L12)） |
| 授权窗口 | 顶栏门禁标记 / 「演练授权」 | 绿点 + 剩余时间充足。注意这块是 **30 秒轮询的快照**，刚被吊销或刚过期的授权会短暂显示旧状态（[GateBadge.vue:21-23](../web/src/ui/GateBadge.vue#L21-L23)），真要判"还能不能投"以后端为准 |
| 审计在落库 | 「证据 → 操作审计」（`GET /audit-logs`，[evidenceApi.js:466](../server/src/api/evidenceApi.js#L466)） | 高危动作都有记录：`site.create` / `site.start` / `site.stop` / `mail_task.real_send` / `evidence.export` |
| 磁盘 | `node server/scripts/purge.mjs --status` | 截图目录未逼近 512MB 配额（[settings.js:103-104](../server/src/platform/settings.js#L103-L104)），`--status` 会打过期文件数 |

大屏注意事项：`/stats/bigscreen` 的 records 带令牌与目标邮箱**明文**，是给操作员本机或受控内网用的（红线写在 [insightApi.js:11](../server/src/api/insightApi.js#L11)），
绝不能接到暴露到公网或对着走廊的屏幕上。

**S2**

**S3**
> 登记一条界面问题（不影响数据与合规）：______，已记入台账编号 ____，演练结束后处理。

## 6. 演练收尾（当天做完）

1. 全部站点收网、发送任务停用；确认 `ss -ltnp` 里没有采集端口；
2. 教育闭环收口：「上钩记录」按处置状态筛 `未处置`，逐个标记为 `已联系` / `已教育` / `已关闭`
   （可批量），目标是把教育覆盖率做到本次演练承诺的水平；
3. 出交付物：按授权生成演练报告（HTML，凭据已掩码）与交付 CSV；**取证导出（明文）只留本机**，不外发；
4. 归档审计：导出 `audit_logs` 与授权文书一起存档，作为合规自证材料；
5. 数据处置：按业主书面确认的方式二选一——
   - 清理：`node server/scripts/purge.mjs --purge-all --confirm=DELETE-ALL`（默认先备份到 `data/backup/`，默认保留授权与素材）；
   - 归档：确认 `exercise.retention_days` 与备份策略，写明保留到期日与责任人；
6. 台账收口：本轮所有 S1/S2/S3 都要有"证据 + 复测人 + 复测时间"三列非空，S2 还要有负责人签字；
7. 复盘：S1/S2 各写一段"下次怎么更早发现"，落到监控点或检查表里，不要只落在记忆里。

## 7. 台账字段（`docs/templates/整改台账模板.csv`）

```
编号,级别,问题摘要,证据位置,整改动作,影响文件,新增断言,状态,负责人,完成日期,复测结论,签字
```

值守期只填前四列 + 负责人 + 发现时间（写在问题摘要里）。后六列由整改人补。
**状态只有三种**：`待处理` / `处理中` / `已关闭`。已关闭必须有复测结论，不许空着。
